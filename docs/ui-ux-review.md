# 주요 화면 UI/UX 검수와 개선

2026-10-19. Impeccable의 기술·사용성 검수와 Ponytail의 최소 공통화 기준을 적용했습니다. 기존 Paperlogy·중립 표면·초록 주요 행동, 인증·원본 보존·삭제 확인 경계를 유지합니다.

## 검수 범위와 계획

제작실, 내 작업물 목록·상세, 제작 분석, 저장공간, 환경 상태, 스타일, 가이드의 8개 화면을 검수합니다. 화면 담당과 CLI/SQLite 담당이 독립적으로 소스를 검토하고 실제 Ego 화면을 비교합니다. 최초 관측 → 회귀 테스트 재현 → 공통 구현 수정 → 데스크톱·모바일 확인의 제한된 검증 순서입니다.

## 공통화 경계

- 공통 `production-ui.js`: 제작 기록의 작업·상태·시간·용량 표현과 정확한 원문 복사 복구. HTTP·업데이트·삭제 경계는 각 기존 기능에서 유지합니다.
- `navigation.json`: Python과 Node의 메뉴 순서·이름·아이콘을 함께 읽고 동일 결과를 회귀 검사합니다.
- `design.css`: 숨김 우선순위, 저장공간 레이아웃, 모바일 배치, 펼침 목표와 복사 상태를 유지합니다.
- 새 UI 프레임워크·의존성·CLI 명령·DB 마이그레이션은 추가하지 않습니다. 기존 기능과 원장을 사용합니다.

## 검증 결과

- 루트 `npm test`: **352/352 통과**, 실패·건너뜀 없음. 마지막 변경 후 다시 실행했습니다.
- 변경 JavaScript 15개 구문 검사, Python 6개 파싱 검사 통과. 제작 원장 25개와 파일 인벤토리 4개 검증 통과.
- Canonical `music-road-skills`에서 공통 HTML 14개 검사와 제작 UI·저장 UI 실행 검사 통과. 변경한 32개 공통 파일과 4개 스킬 지침의 원본 일치를 확인했습니다.
- 실제 Ego: 8개 화면 × 1440/390/320px, **24개 조건**에서 문서 가로 넘침 없음, Paperlogy 실로딩, 보이는 `hidden` 컨트롤 없음, 끊어진 `aria-labelledby` 없음, 44px 미만 펼치기 목표 없음.
- 격리된 두 음악 그룹: 메인 1개·추가 요청 1개 분리, 타 그룹 요청 제외, 복사 거절 시 정확한 원문 선택·중복 복사란 방지, 좋아요 저장·검색·필터 결과 수 확인. 공개 CLI에서도 같은 SQLite 좋아요와 그룹별 요청을 확인했습니다.
- 실제 제작실: 모드를 전환해 저장 버튼 하나만 보이는지 확인했습니다. 표시 설정이 생략된 이전 자료도 화면을 막지 않도록 보완했습니다.
- 통신 실패: 모든 상태 영역의 로딩 종료·다시 시도 활성화와 한국어 복구 안내를 확인했습니다. 스킬 업데이트 확인창은 전체 관리 묶음 범위를 명시합니다.
- 실제 저장 UI: 캐시 계획 → 취소 → 일괄 정리 계획 전환에서 활성 계획이 일치함을 확인했습니다. 확인 실행은 브라우저의 모의 응답으로 **서버 삭제 없이** 검사했으며, 진행 중 Escape/취소/새로고침 차단·요청 한 번·완료 뒤 닫기 복구를 확인했습니다.
- 독립 최종 코드 검수에서 새 차단 결함은 발견되지 않았습니다. LSP 진단 서비스는 연결 종료로 이용하지 못해 구문·실행 회귀 검사로 대체했습니다.

## 한계

자동 디자인 검출기는 파서 모듈이 없어 정규식 축소 모드로 실행됐습니다. 접근성·대비 전체 적합성을 보증하지 않으며 실제 DOM·화면·키보드 검수와 함께 판단합니다. 기존 영상은 재렌더하지 않았고 모델 추론·실제 사용자 파일 삭제·운영 프로그램 업데이트는 실행하지 않았습니다. `quick_validate.py`는 설치된 Python들에 PyYAML이 없어 실행할 수 없었으며, 새 패키지를 설치하지 않고 스킬 frontmatter·경로·원본 일치와 실제 기능 실행 검사로 보완했습니다. 전체 WCAG 적합성, 모든 OS·보조공학·브라우저 조합을 보증하지 않습니다.
