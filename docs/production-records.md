# 제작 기록과 성능 원장

Road Music은 음악과 모션그래픽 제작 요청, 실제 작업 시간, 결과 요약과 생성 파일 메타데이터를 프로필 `storage.sqlite3`에 기록합니다. 음원·영상·프레임·엔진 로그는 데이터베이스에 복사하지 않고 기존 프로젝트 파일로 유지합니다.

## 기록 기준

사용자가 음악 또는 영상 제작을 처음 요청하면 그 원문을 메인 프롬프트로 기록합니다. 제목·가사·음악·영상·연출 변경처럼 새로 요청한 수정은 각각 프롬프트 이력으로 기록합니다. 같은 요청을 엔진의 내부 단계마다 복제하지 않으며, 실제 생성·분석·렌더만 해당 `requestId`에 연결합니다.

작업은 `production:task-start`로 시작하고 `production:task-finish`로 끝냅니다. 종료 기록에는 실제 소요 시간, 결과 길이·프레임 수, 간결한 AI·결과 요약, 확인한 파일 경로만 넣습니다. 값이 없으면 추정하지 않고 알 수 없음으로 남깁니다.

```bash
node cli/road-music.js production:request --json '{
  "project":"/absolute/path/to/project",
  "domain":"music",
  "title":"새 음악",
  "intent":"initial-generate",
  "prompt":"요청한 음악 제작 프롬프트"
}'
```

반환된 `requestId`를 제작 작업에 연결합니다.

```bash
node cli/road-music.js production:task-start --json '{
  "project":"/absolute/path/to/project",
  "domain":"music",
  "taskType":"generation",
  "engine":"ace",
  "requestId":"반환된-48자리-ID"
}'
```

완료 뒤 같은 `taskId`에 실제 값만 기록합니다.

```bash
node cli/road-music.js production:task-finish --json '{
  "taskId":"반환된-48자리-ID",
  "status":"succeeded",
  "elapsedMs":125000,
  "mediaSeconds":48,
  "resultSummary":"48초 완성 음원 생성",
  "files":[{"path":"/absolute/path/to/final.mp3","role":"final"}]
}'
```

## 조회와 대시보드

`production:projects`, `production:prompts`, `production:tasks`, `production:files`는 프로젝트별 목록을 cursor로 나누어 반환합니다. `nextCursor`가 있을 때만 다음 페이지를 요청합니다. `production:dashboard`는 완료된 실제 측정값을 기반으로 전체·프로젝트별 요청 수, 생성·수정 횟수, 평균 소요 시간, 느린 작업을 집계합니다.

평균은 같은 제작 영역, 작업 종류, 엔진/모델 조건에서 완료된 작업끼리만 비교합니다. 다른 조건, 실패·취소, 큐 대기와 사용자 검토 시간은 같은 평균으로 합치지 않습니다. 데이터가 부족하면 비교 기준 부족으로 표시합니다.

HTML의 음악별 작업물 상세에서는 메인 프롬프트와 이력을 복사할 수 있고, 결과 파일을 작업별로 볼 수 있습니다. 대시보드는 페이지 단위 조회로 프로젝트가 많아도 전체 이력·파일을 한꺼번에 읽지 않습니다.

## 버전 기록과 삭제

`production:components`는 앱·CLI·스킬 묶음의 설치 버전과 마지막 업데이트 확인을 보여 줍니다. 이 기록은 알림·비교용입니다. 실제 설치 완료는 현재 설치본의 버전, manifest, 체크섬과 설치 검증으로만 판정하며 SQLite의 오래된 기록만으로 설치 성공으로 간주하지 않습니다.

프로젝트·음악 그룹을 `storage:project-remove-preview` 또는 `storage:group-remove-preview`로 확인해 제거하면 연결된 프롬프트·작업·파일·경로 이력도 SQLite에서 정리합니다. 일반 캐시 정리는 제작 원장과 최종 결과물을 삭제하지 않습니다.

프롬프트는 복사 가능하므로 API 키·비밀번호·인증 헤더·개인 연락처를 입력하지 마세요.


## 지표의 정확한 기준

메인 요청은 프로젝트·분야별 첫 사용자 원문입니다. 요청 횟수에는 engine 입력을 합산하지 않습니다. 생성 횟수는 성공한 generation/generate/render, 수정 횟수는 성공한 revision/lyrics/title/replace/restore 작업입니다. 수정 요청 수와 수정 성공 횟수는 별개입니다. 평균·중앙값·p95와 일별 추이는 성공 측정 기준이고, 총 소요 시간은 실패·취소의 측정 비용도 포함합니다. 내부 단계는 유형별 분석에서 볼 수 있으며 전체 시간에는 중복 합산하지 않습니다.

미디어 1초당 제작 시간은 elapsedMs/1000/mediaSeconds이며 작을수록 빠릅니다. fps는 frameCount*1000/elapsedMs입니다. 느린 작업은 같은 조건·같은 단위 표본이 3개 이상일 때, 자신을 제외한 평균의 1.5배를 넘긴 경우입니다. 시간·재생 길이·프레임 측정이 없으면 0을 만들지 않습니다. 생성 파일은 작업 폴더 안에서 200개씩 나눠 메타데이터를 기록하며, 접근 실패는 불완전 상태와 경고를 남깁니다.

긴 프롬프트 JSON은 `--stdin` 또는 `--file`로 전달하세요. Python 기록 도구로 전달할 때도 표준입력을 사용합니다. 과거 작업의 누락된 최초 자연어 요청·측정값은 추정해 채우지 않습니다. HTML 목록은 자동 이어보기와 더 보기를 지원하고 표시 행을 120개로 제한합니다.

## 그래프와 응답 요약

일별 그래프는 최근 14일의 완료 작업 수와 시간을, 평균 시간 그래프는 소요 시간이 긴 작업 조건 12개까지 표시합니다. 음악 길이·작업·엔진·모델이 다른 막대의 길이를 성능 순위로 해석하지 마세요. 느린 작업 판정은 비교 가능한 같은 조건의 표본만 사용합니다.

에이전트가 실제 결과를 검수하는 `review` 단계에는 요청에 대한 AI 응답과 얻은 결과를 각각 간결하게 남깁니다. HTML은 두 요약을 함께 보여 주며, 이 단계는 새로운 음원·영상 생성 횟수로 계산하지 않습니다. 소스 묶음의 버전 관찰은 실제 설치 완료 기록과 구분해서 표시합니다.

## 그룹 상세에서 요청·결과 보기

내 작업물에서 음악 그룹을 열고 **제작 기록** 메뉴를 누르면 해당 원음 그룹의 메인 프롬프트, 수정 요청, AI 응답·결과 요약, 작업과 생성 파일을 확인합니다. 다른 그룹의 기록은 섞지 않습니다. 원문은 각각 복사할 수 있으며 이전 요청·작업·파일은 더 보기로 읽습니다. 버전·변경 이력은 완성 파일의 버전 비교이고, 제작 기록은 요청부터 결과까지의 과정입니다. 기록이 없으면 이전 원문을 추정하지 않고 미기록으로 안내합니다.

## 업데이트 확인·실행

제작 분석의 프로그램·스킬 버전 상태에서 **업데이트 확인** 후 새 버전의 **업데이트**를 선택합니다. 대상과 버전을 확인하는 창에서 실행하면 진행 막대와 처리 단계, 완료·실패 안내가 표시됩니다. 정확한 진행량이 없을 때는 불확정 막대를 사용합니다. 화면의 일시적 연결 오류는 설치 실패와 구분하고 기존 작업 상태를 다시 조회합니다. 응답을 잃었다고 설치 요청을 자동 재제출하지 않습니다.

CLI는 검증한 새 폴더의 설치 경로를 결과에 표시하며 현재 제작실의 실행 경로를 바꾸지 않습니다. 앱은 실제 재시작 후 실행 버전이 확인되어야 적용 완료입니다. 소스 체크아웃 스킬은 변경을 보호하기 위해 확인만 제공하며, 관리 설치가 있는 묶음만 업데이트합니다. 중단된 설치의 결과를 확인할 수 없으면 재실행을 차단하고 확인 필요 상태를 유지합니다.

## 음악 그룹과 요청 목록 표시

이미 음악 그룹에 귀속된 프로젝트 경로에 다른 음악의 `groupId`를 넣으면 쓰기를 거절합니다. 새 음악은 새 프로젝트에서 기록하세요. 기존 요청·엔진 입력·부모 작업과 재사용 작업 ID도 서로 다른 음악에 연결할 수 없습니다. 초기 미연결 기록의 첫 귀속 흐름은 유지하며 과거 원장을 추정해서 수정하지 않습니다.

CLI의 전체 요청에는 메인 요청도 포함됩니다. HTML은 이를 메인 영역에 한 번 표시하고 추가 요청 목록에서는 제외합니다. 요청 수와 결과 집계는 SQLite에 실제 기록한 수입니다.

실제 생성 성공 시 선택된 최종 음원 파일만 스트리밍 해시로 확인해 생성 원장의 그룹을 연결합니다. 처음 비어 있던 그룹이 정해지면 같은 프로젝트의 null 프롬프트·작업·파일도 함께 연결합니다. 이미 귀속된 다른 그룹은 변경하지 않으며, 과거 미귀속 기록을 복구할 때도 검증된 해시와 동일 requestId·원문을 쓰므로 요청 수·시각·측정값은 유지됩니다. 전체 음악 폴더나 Git을 재스캔하지 않습니다.

## 프로젝트 비교와 음악 그룹 시간

`production:projects`의 `performance`는 해당 조회 조건의 상위 작업을 프로젝트별로 집계한다. 음악·영상 누적 시간과 성공 평균, 측정·미측정·실패·취소 수를 분리해 비교한다. `production:dashboard`의 `groupSummaries`와 그룹 범위의 `stageBreakdown`은 내 작업물 시간과 과정별 파이 그래프의 기준이다. `groupIds` 배열은 최대100개 그룹만 일괄 조회하며 같은 필터 범위를 유지한다. 파일·전체 작업을 내려받아 클라이언트에서 합산하거나 하위 단계를 중복 집계하지 않는다. 누적 시간은 실제 경과 시간과 다르며 미측정은 null로 보존한다.
