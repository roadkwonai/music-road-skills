# 비트·모션·가사·섬광을 실제 완성본까지 검증하기

새 음악으로 제작하거나 비트·모션·가사 싱크를 수정할 때 읽고 적용한다. 문서만 갱신하는 요청에는 영상 생성·재렌더를 시작하지 않는다. playlist는 기존 `captions.md`·`music-direction.md`, MV는 `vocal-caption-timing.md`·`rhythm-typography.md`의 원문·표시·시간 계약을 함께 유지한다. 여기의 절차는 네이티브 Showreel과 기존 프리셋을 사용하며 새 렌더 엔진이나 프리셋 등록 명령이 아니다.

## 1. 현재 음원과 가사 시계를 먼저 고정

- 원곡 절대 경로·SHA-256·실제 길이, 분석/정렬 WAV의 별도 해시·샘플레이트·원곡 cut offset을 기록한다. 같은 제목·순번·길이의 과거 산출물을 현재 테이크로 단정하지 않는다. 현재 파일이 달라지면 가사·비트·FFT·구간 시각을 함께 다시 확인한다.
- 확정 가사의 문장·순서·띄어쓰기를 보존한다. 과거 정렬 실행 파일은 재사용할 수 있으나 **새 현재 PCM과 해당 원문**으로 실행한다. 파일명만 같은 과거 정렬 결과를 복사하거나 기존 해시만 고쳐 연결하지 않는다.
- ASR가 반복·환각·긴 세그먼트를 내면 전체 결과를 균등 배분하지 않는다. 문제 구절의 앞뒤를 포함한 겹치는 짧은 구간을 다시 분석하고, 캐시된 다른 모델/명료화 분석과 대조한다. 정렬용 대역 처리본은 보조 분석용이며 최종 음악으로 교체하지 않는다. 새 모델 다운로드나 유료 전송은 권한으로 추정하지 않는다.
- 기존 강제 정렬 도구가 있을 때만 정확한 원문과 새 PCM을 넣어 보조 근거로 쓴다. 강제로 입력한 문장이 실제로 불렸다는 증거는 아니며, 약한 선행 토큰/긴 무음 속 토큰을 onset 정답으로 쓰지 않는다. 근거가 좁은 겹침 구간에서 일치하지 않으면 불확실성·부분 누락을 보존한다.
- `timing-review.json` 등에 cue별 onset/end·출처·offset·근거 파일·불확실성·수정 전후와 실제 청취 여부를 남긴다. 자동 정렬만 수행했다면 `auto-asr-unreviewed` 또는 부분 초안 상태를 유지한다. 문구를 알고 있어도 단어/음절 경계를 만들어 넣지 않는다.
- ‘전주 무가사’는 실제 **구간별**로 판정한다. 도입 가창 → 간주 → 본절처럼 가사가 먼저 나오는 곡도 있다. 검토자에게 무가사 범위와 해당 cue를 정확히 전달한다. 곡의 시작부터 첫 본절까지 일괄 자막을 숨기지 않는다.

## 2. 실제 소리의 강약과 화면 사건을 연결

기존 Showreel 분석의 beats/downbeats는 템포/박자 가정, hits는 강세 후보, energy는 에너지다. 어느 것도 실제 킥·스네어 분리나 장르 판정이 아니다. 벌스·각 후렴·브리지의 실제 hit 개수/간격과 화면 반응을 확인한다. 강한 전역 피크만 남겨 후렴 화면이 오래 정지하면, 단순히 효과 크기만 올리지 말고 로컬 변화 검출을 보강한다.

기존 NumPy·FFmpeg가 있는 Python으로 현재 스킬의 `scripts/audio_onsets.py`를 실행한다. `<스킬절대경로>`는 **실제로 읽은 설치본**이다. 여러 곡이면 각 원곡 또는 시계가 확인된 준비 PCM을 곡별 분석한다.

```bash
"$SHOWREEL_PYTHON" "<스킬절대경로>/scripts/audio_onsets.py" \
  --audio '/절대/현재-음원.mp3' --out '/절대/새-출력/onsets-local.json'
```

도구는 16k mono, 1024-sample 창/160-hop, 60–6500Hz의 양의 log spectral flux, 로컬 약 5초의 70% 문턱, 기본 최소 간격 0.27초로 사건 후보를 구한다. 검증된 출발값이며 모든 곡의 비트 정답이 아니다. `--min-spacing`은 곡의 호흡에 맞춰 조정할 수 있다. 무음에는 사건을 만들지 않는다. `strength`는 해당 분석의 상대 단서이며 다른 곡의 절대 강도와 비교하지 않는다. 분석 도구는 음원을 변경하지 않고 기존 출력 덮어쓰기를 거부한다. Python/NumPy/FFmpeg가 없으면 기존 설치를 찾고 해당 분석의 제한을 보고하며 자동 설치하지 않는다.

**분석 JSON 생성만으로 모션 적용은 끝나지 않는다.**

- 출력은 `events[].timeSeconds/strength`, 입력 파일 해시, 분석 설정을 가진 별도 데이터다. 네이티브 `analysis.json`을 덮거나 지원되지 않는 direction 필드를 추가하지 않는다.
- 커스텀 장면의 계획/JS에 이 사건을 명시적으로 읽거나 bake하고, 실제 함수를 호출하도록 연결한다. 원곡 사건 `s`는 `track.startSample/sampleRate + s - track.source.cutStartSeconds`로 출력 시계에 옮기고 컷 밖 사건을 버린다. 준비 PCM이 이미 출력 시계라면 이 이동을 다시 적용하지 않는다. 컷/프리롤 등 매핑 근거를 기록한다.
- 기존 direction 템플릿을 유지하면 허용된 효과 스키마와 간격 제약에 맞춰 선택 사건만 전달한다. 지원하지 않는 표현은 새 프로젝트의 네이티브 장면으로 구현한다. 오래된 고정 템플릿이 새 JSON을 자동 소비한다고 가정하지 않는다.
- 작은 리본·깊이·대역 반응과 큰 패널·카메라·컷 사건을 구분한다. 모든 후보에 큰 효과를 발생시키지 말고 구간 강도·최소 휴지·가사 여백으로 선별한다. 조용한 프레이즈는 읽기/정착을 유지한다.
- 실제 사건 시각의 프레임과 사건을 제거한 동일 시각을 비교해 픽셀이 변하는지 확인한다. FFT·에너지는 각각 실제 데이터로 연결하고 가짜 스펙트럼이나 사인파를 측정값으로 부르지 않는다.
- native `timeline.json.music`의 파일/믹스 설정과 `reel/timeline.js`의 analyzed `music.hits/energy/beats`는 다른 형식일 수 있다. 형식이 다르면 JSON 전체를 JS에 대입하지 말고 기존 분석 payload를 보존해 장면/cue만 갱신한다. 이전·이후 hit 수, envelope 길이와 대표 시각의 실제 값, 원음/가사 시계가 유지됐는지 확인하고 분석값 누락을 0으로 조용히 넘기지 않는다.

## 3. 모션의 무게·가독성과 결정성

기술 검사 통과와 음악·미술 적합성을 따로 판정한다. 모션 계획에 음악/가사 근거 → 모티프 상태 변화 → 실제 함수/cue → 진입·정착·퇴장 → proof를 연결한다. 새벽·열차·7종·26구간 등 지난 작품의 개수/소재를 다음 곡의 기준으로 고정하지 않는다. 후렴마다 같은 슬램을 반복하기보다 깊이·구도·재질·후속 움직임을 변주한다.

- 캔버스는 매 프레임 transform/alpha/composite/filter/경로를 초기화하고 각 레이어의 save/restore를 짝지어 UI·가사에 상태가 새지 않게 한다. 조리개는 원하는 이미지를 clip 안에 그리며 전체 캔버스를 지워 투명 구멍으로 만들지 않는다.
- glyph/mask/입자와 이미지 decode는 setup에서 준비한다. render는 시간만으로 계산하고 누적 상태·실시간 난수에 의존하지 않는다. T04 글자 입자와 T05 자모 조립을 실제 구현대로 구분해 보고한다.
- 정상/역순/재방문 seek를 동일 시각에서 비교한다. GPU 래스터 차이가 재현되면 주 Canvas뿐 아니라 캐시된 이미지 crop·glyph·grain 등 offscreen 표면도 분리 점검한다. 필요한 표면에만 `getContext('2d', {willReadFrequently:true})` 등 소프트웨어 경로를 시험하고 동일성·속도를 다시 검증한다. 모든 캔버스나 설치 엔진을 일괄 바꾸지 않는다.
- 필수 문장 전체는 `[start,end)`부터 읽혀야 한다. 조립·입자·마스크·페이드 때문에 본문을 늦게 공개하지 않는다. 장식 문구는 별도 레이어다. 줄바꿈은 원문 공백과 실제 폰트의 글자 폭으로 확인하고, 텍스트 영역과 글꼴 로딩/대체 여부를 실제 프레임에서 본다.
- 가사/UI는 카메라·섬광에 휘둘리지 않는 읽기 레이어로 둔다. 첫 카드가 있으면 모든 레이어 위에서 덮고, 0.5초 카드의 최종 15프레임과 다음 프레임 잔상을 실제 `--sub 4` 출력에서 확인한다(30fps 기준). 음악·가사 전체 시각을 카드에 맞춰 이동하지 않는다.

### 정지 포스터와 실제 모션을 구분

- 사진 위 얇은 선·반투명 판·같은 단어가 반복되고 곡의 전개가 보이지 않으면 효과 수만 늘리지 말고 약한 장면의 주된 형태·구도·운동을 다시 설계한다. 그래픽 중심을 원한 곡에서는 모티프가 화면을 구성하게 하고 사진은 필요에 따라 창·형태 내부로 제한할 수 있다. 사용자가 지정한 사진 중심/차분한 형식을 강제로 바꾸지는 않는다.
- 계산한 `x/y/scale/angle`이 실제 draw/transform에 전달되는지 확인한다. 이동값을 계산해도 고정 좌표를 그리면 정지 화면이다. 사건 직전 → 이동 중 → 착지 후의 연속 strip으로 변화를 확인하고, 실제 사건을 제거한 동일 시각과도 비교한다. transform과 좌표에 같은 이동을 중복 적용하지 않는다.
- 작은 onset/FFT 반응, 선별한 큰 사건의 이동·압축, 프레이즈 경계의 구도 전환을 나눈다. 큰 움직임은 가속 후 읽을 수 있는 위치에 정착시킨다. 이때 이동 목표와 이전 목표를 실제 사건 시각으로 보간하고 누적 프레임 상태는 쓰지 않는다. 모든 박에 같은 전면 점멸·펀치를 붙이지 않는다.
- 주요 훅의 반복은 같은 모티프를 인식시키되 색·깊이·거리·경로·마무리 결과를 발전시킨다. 첫/둘째/마지막 후렴의 차이를 단순 크기 배수나 효과 이름만으로 끝내지 않는다. 벌스·브리지·여운의 조용한 호흡은 음악 근거와 함께 남긴다.

### 가사 소재가 형태와 동작이 되게 하기

아래는 연출 후보이며 장르별 고정 템플릿이나 새 helper 지원값이 아니다. 가사에 해당 소재가 없으면 그대로 복제하지 않고 곡의 실제 소재로 설계한다.

| 구절의 단서 | 조형과 동작 후보 | 실제 확인 |
|---|---|---|
| 이어짐·선택·앞으로 | 선/리본의 분기·합류, 형태를 따라 전진하는 방향표 | 장소 사진만 교체하지 않고 형태의 상태가 변하는가 |
| 불빛·별·기타 줄·박자 | 점이 현으로 연결되고 타격 후 감쇠 진동, 피킹의 이동/정착 | 실제 onset·대역에 반응하며 악기 분리 결과로 오인하지 않는가 |
| 불안·놓기·던지기 | 조각의 탄도·회전·퇴장과 남는 여백 | 의미가 읽히는 크기/대비이고 필수 자막을 가리지 않는가 |
| 작은 하늘·돌파·열림 | 작은 창이 넓어지고 다음 공간/형태로 연결 | 여러 편집 구간을 지나도 확장이 이어지는가 |

- 장식 강조어를 쓴다면 해당 구절의 의미와 연결한다. 가사가 다른 구간에 예전 placeholder나 범용 ‘목소리’ 같은 단어를 남기지 않는다. 연결할 단어가 없으면 모티프만 쓰며 가사를 새로 만들지 않는다. 장식 키워드의 상태 변환은 승인 원문 자막의 변경 권한이 아니다.
- 큰 활자도 실제 서체의 `measureText` 폭과 ascent/descent, 최종 scale·위치·그림자 여백으로 배치한다. 밝은 면/어두운 면과 사진 위의 글자 대비를 각각 확대해 확인한다. 가라오케 근거 없이 장식용 조립을 가창 싱크로 부르지 않는다.
- T05처럼 glyph를 clip으로 나눈 조각을 이동시킬 때는 clip 영역과 glyph가 **함께 이동**하도록 맞춘다. 도착 영역에 고정 clip을 두고 glyph만 밖에서 이동시키면 마스크 리빌에 가깝다. 같은 글자를 중복 합성해 글자 구조가 무너지지 않는지 완성 프레임에서 본다.
- 브리지의 창 확장처럼 여러 scene에 이어지는 동작은 scene별 local progress로 재시작하지 말고 해당 구간 묶음의 시작/끝 시계로 계산한다. 의도하지 않은 축소·초기화가 없는지 경계를 포함한 strip으로 확인한다.

## 4. 섬광을 줄이면서 임팩트 유지

정지 프레임이나 저속 미리보기만으로 섬광을 판단하지 않는다. 최종과 같은 fps·서브프레임·크롭·팔레트로 원음 포함 native proof를 만들고 실제 완성 믹스에 `motion_check.py`와 `qa_check.py`를 실행한다. 최종 전곡의 초당 3회 초과 경고 구간은 수정한다. 총 섬광 수만 세어 통과시키거나 임계값을 낮추지 않는다.

실패 구간에서는 동시에 켜지는 효과 수, 밝은 패널 면적/불투명도, 고대비 교차, 이동 속도와 트리거 간격을 하나씩 조절한다. 전면 점멸 대신 부분 타일·방향 이동·관성 있는 확대와 충분한 정착으로 타격감을 만든다. ‘내일로 달려’의 패널 1초 이동·높이 500px는 해당 장면의 해결 사례이며 공통 합격값이 아니다. 색·면적·동시 효과가 달라지면 같은 값도 재검사한다.

벌스·주요 훅·브리지/마지막 절정 등 성격이 다른 핵심 구간을 각각 원음 포함 native proof로 검사한다. 전곡의 완화된 길이 기준 통과로 약한 짧은 구간을 숨기거나, 통과하려고 검수 범위를 길게 바꾸지 않는다. 의도된 저운동은 해당 시각과 음악/미술 근거를 남긴다.

proof → 수정 → **동일 시각/길이/설정**의 proof로 변화와 회귀를 확인한다. 다른 길이의 proof와 전곡 p90을 통제된 전후 비교로 보고하지 않는다. 조용한 장르의 의도된 정착은 시각/음악 근거를 남기며 큰 움직임 지표만 높이려고 과장하지 않는다.

## 5. 최종 버전과 증거를 함께 납품

- proof 통과 후 전곡을 렌더하고 전체 디코딩·규격·길이/프레임·음량·움직임·섬광을 다시 검사한다. 부분 proof 통과를 전곡 통과로 대체하지 않는다. 렌더러는 동시에 하나만 실행한다.
- 시작/중간/후반의 원곡과 최종 오디오를 대조해 일정 지연과 누적 드리프트를 구분한다. native limiter의 지연이 있으면 실제 설정과 측정값을 기록한다. 지난 곡에서 관측한 3ms를 새 곡에 가정하거나 모든 자막을 그만큼 이동하지 않는다. AAC/음량 처리본을 원본과 무손실 동일하다고 부르지 않는다.
- 번인 자막/SRT/타이밍 JSON이 같은 최종 데이터인지, 모든 cue 시작 전후·종료·원문·실제 글자 범위가 일치하는지 확인한다. 자동/청취/단어 정렬의 검수 범위를 별도로 보고한다.
- 전곡 콘택트 시트가 **실제로 생성되어 열리는지** 확인한다. native QA가 pass라도 시트가 비었으면 미완료다. 실제 FFmpeg9의 `-vsync` 제거 오류는 설치본을 건드리지 않는 로컬 사본에서 해당 추출 옵션만 `-fps_mode`로 바꾸고 버전·원본/사본 해시·diff·재QA를 남긴다. 성공한 환경에 미리 패치하지 않는다.
- 시트·확대 프레임·연속 strip에서 글자/얼굴 잘림·레이어 누수·빈 화면·반복·최약 구간을 검토하고 가능하면 독립 시각 검토로 보완한다. 실제 청취/전 프레임 재생을 하지 않았다면 수행했다고 보고하지 않는다.
- 렌더 재사용은 동일 코드·설정·자산·폰트·시계와 청크 프레임 수를 확인한 경우만 한다. native cache signature와 파일 provenance SHA-256은 목적과 알고리즘이 다를 수 있으므로 설치된 renderer의 실제 산식을 확인하고 혼용하지 않는다. 코드가 바뀐 proof 청크를 부분 함수가 같다는 이유로 전체 코드가 같은 캐시처럼 재사용하지 않는다. 최신 프로젝트 진입 파일과 영상·SRT·썸네일·미리보기·검수 보고를 같은 버전으로 고정하고, 이전 proof를 최종 파일로 게시하지 않는다. Studio 사용 시 기존 사용자 표시/피드백을 보존해 최신 산출물을 등록한다.

이 절차의 근거는 2026-10-18 ‘내일로 달려’의 현재 음원 재정렬과 v1/v2 native proof 실패·수정, 최종 6,149프레임 검수다. 기술 수치와 미술 개선은 각각의 증거로 보고하며 모든 전곡 지표가 이전보다 높아졌다고 확대하지 않는다. 결과의 숫자·팔레트·가사는 회귀 근거이며 다음 곡의 디자인/합격 기준이 아니다.
