# 가창에 맞는 자막

현재 테이크로 다시 정렬하거나 ASR 반복·환각을 보완할 때는 [원음·정렬 근거와 최종 검증](production-quality.md)을 함께 적용한다. 겹치는 짧은 구간의 근거와 cue별 불확실성을 남기며, 자동 정렬 상태를 청취 검수 완료로 승격하지 않는다.

원문·띄어쓰기·줄 순서는 보존한다. 가창 시각은 음악의 비트나 글자 수로 대체하지 않는다.

## 음악만 있고 가사가 없을 때

- 보컬/연주곡 여부와 사용자 자막 요청을 먼저 확인한다. 연주곡에는 ASR·가창 자막·가라오케를 만들지 않는다. 필요한 제목/장식 문구는 가사와 구분한다.
- 보컬곡은 같은 곡의 기존 확정 가사·SRT를 우선 찾고, 없으면 설치된 ASR/정렬 수단으로 가사와 시각 초안을 추출한다. 새 모델 설치·유료 API 권한은 추정하지 않는다. 확정 원문과 ASR 초안의 출처·신뢰도·불확실한 구절을 구분한다.
- 불확실한 단어를 지어내거나 새 가사를 써서 메우지 않는다. 신뢰할 수 있는 구절만 표시하고 불확실한 초안은 별도로 남기거나, 자막 자료가 없는 상태로 가능한 영상 본편을 계속 제작한다. 자막 범위와 미확정 구절을 보고하며 완전한 가사 자막이라고 주장하지 않는다.
- 사용자가 정확한 전곡 가사/자막을 필수로 요구했고 이를 확보할 수 없으면 필요한 원문 등 누락 입력만 확인한다. 독립적인 연출·보드·자산 작업은 계속하되 그 필수 요건을 완료로 처리하지 않는다.

## 선행과 지연의 원인을 분리한다

- 첫 인식 토큰이 구절의 첫 음절인가: 앞 단어가 누락·로마자 음차·오인식되어 구절 중간/마지막 토큰만 확정된 경우, 그 앵커를 구절 시작으로 쓰면 늦어진다. 겹친 구간 재인식·음성상 유사 토큰·반복 구절·가창 신호를 교차 확인하고 근거를 남긴다.
- 첫 단어의 DTW 점도 실제 첫 발성보다 뒤의 모음 중심에 놓일 수 있다. 첫 토큰이라는 이유만으로 onset 정답으로 확정하지 않는다. 사용자가 특정 문구의 지연을 확인하면 해당 반복 구절의 첫 토큰 경계·자음/모음 attack을 구절별로 재점검하고 짧은 원음 proof로 확인한다. ASR와 믹스 대역 신호는 보조 근거이며, 반주를 순수 보컬/음소 경계로 오인하지 않는다.
- 자막 activeId와 읽히는 시각을 구분한다. 실제 onset gate가 맞아도 조립·마스크·낮은 opacity 때문에 전문이 나중에 읽히면 지연이다. 싱크 우선 요청에서는 문장 전체를 onset에 읽을 수 있게 하고 장식 동작은 그 뒤에 둔다.
- ASR segment 시작이 반주·숨·긴 무음을 포함하는가: 세그먼트 시작을 곧 가창 onset으로 쓰지 않는다. 실제 가창 근거가 있는 토큰·보컬 명료화/분리·정렬 결과와 비교한다.
- 두 줄이 하나의 긴 segment로 합쳐졌는가: 다음 줄을 첫 줄과 함께 미리 표시하지 않는다. 근거 있는 각 줄 onset으로 나누거나 같은 두 줄 레이아웃에서 해당 줄만 시각에 맞춰 공개한다. 근거 없는 내부 경계는 만들지 않는다.
- 애니메이션을 큐에 착지시키려고 미리 시작했는가: glyph 캐시는 미리 만들 수 있지만 기본 표시 gate는 추정 가창 시작점에 둔다. 사용자가 늦음보다 소폭 선행을 선호하면 그 선호를 우선해 표시 시작을 조금 앞당긴다. 영상 하드컷의 반 프레임 보정을 자막 onset에 무조건 재사용하지 않는다.

## 근거와 수정

원음과 확정 가사를 입력으로 가능한 기존 ASR/가창 정렬/보컬 분리 런타임을 먼저 확인한다. 설치 모델을 재사용하고 새 모델 다운로드·유료 API·엔진 변경 권한을 추정하지 않는다. 짧은 잘라낸 ASR이 환각을 내면 그것으로 강제 확정하지 않는다. 전역 지연값은 일정한 오프셋이 실측됐을 때만 쓰고 구절마다 다른 오류의 해결책으로 쓰지 않는다.

구절 onset/end, 원문, 근거 파일과 시각, 신뢰도, 전후 차이를 남긴다. 토큰 시각과 실제 한국어 단어/음절 시각은 다르므로 검증 없는 가라오케 동기를 주장하지 않는다. 불확실한 구절은 재검토하고 검증 범위를 보고한다.

소폭 선행 요청에서는 인식/가창 추정 앵커와 실제 표시 시작을 구분해 이전 시각·수정 시각·선행 폭·사용자 선호를 기록한다. 몇 프레임 정도의 작은 선행부터 구절별로 검토하며, 지적된 동일 가사의 반복 구간도 빠짐없이 확인한다. 첫 토큰을 정답으로 고집해 늦게 읽히게 하지 않는다. 앞 구절 종료와 가창 사이의 여유를 확인하고 긴 무음에 다음 가사가 먼저 뜨거나 자막이 겹치도록 일괄 당기지 않는다.

## 실제 합성 검수

도입·각 후렴·긴 segment/무음 전후의 원음 포함 proof를 만든다. 오프닝 표지를 쓰면 cover 퇴장 전에는 가사 glyph가 0이고, 다음 본편 화면에서 첫 가사가 정상적으로 읽히는지도 같은 proof에서 확인한다. 정한 표시 시작 직전 프레임은 해당 구절 비활성, 직후는 올바른 원문 전문이 읽혀야 한다. 의도한 소폭 선행과 무단 선행을 구분하고, 가창 시점에 이미 충분히 읽히는지 확인한다. 합친 두 줄의 다음 행이 먼저 공개되지 않는지 확인한다. 최종 서브프레임 렌더에서도 경계를 검사한다. JSON/SRT만 맞고 실제 글자 조립·마스크 때문에 늦게 읽히는 경우를 통과시키지 않는다.

원본 음원 해시와 실제 정렬에 사용한 WAV의 해시·샘플레이트를 따로 기록한다. 자른 파일은 원곡에 대한 절대 시작 offset을 함께 고정해 상대 ASR 시각을 원곡 시각으로 환산한다. 타임라인과 SRT를 갱신할 때는 이 입력 버전과 최종 자막 데이터가 일치하는지 확인한다.

오프닝 길이만 바꾼 경우 원곡 시계의 구절 앵커와 원문은 보존하고, 영상용 자막과 본편의 공통 offset만 갱신한다. 오프닝 화면의 재생속도를 조절해도 본편 음악·자막까지 같은 비율로 압축하지 않는다. 최종 오디오가 올바른 원곡 위치에서 시작하는지와 실제 번인 자막·SRT가 같은 시각으로 이동했는지를 따로 검증한다. 해시·파형 상관이나 무음 재생 확인을 직접 청취·음소 정렬 완료로 보고하지 않는다.

## 설치된 whisper.cpp 1.9.5의 DTW 경로

이 버전과 캐시 turbo가 확인된 환경에서는 `-m <ggml-large-v3-turbo.bin> -dtw large.v3.turbo -nfa -l ko -ojf`를 사용할 수 있다. `-dtw`는 점 구분 프리셋이고 모델 파일 경로는 `-m`에만 넣는다. 기본 flash attention을 끄지 않으면 DTW가 비활성화되므로 실제 로그의 `dtw = 1`, `flash attn = 0`과 출력 토큰을 확인한다.

결과는 `tokens[].t_dtw / 100 + clipOffsetSeconds`이며 기존 `offsets`/`timestamps`와 구분한다. 이는 ASR가 인식한 토큰에 대한 실험적·대략적인 음성 위치이며 승인 가사 자체를 입력해 강제 정렬하는 기능이 아니다. 누락/오인식 텍스트나 긴 음의 끝을 자동 복구하지 않으며 한국어 단어/음절의 완전한 동기로 주장하지 않는다. 원문과 맞는 실제 토큰의 보조 근거로 쓰고 일반 segment start와 차이를 비교한다. 버전·모델이 다르면 설치 도움말과 해당 공식 구현을 다시 확인한다.
