# Road Music Showreel MV

## 제작 기록

실제 Showreel MV 제작과 수정은 [제작 기록 스킬](../road-music-production-records/SKILL.md)을 함께 적용한다. 사용자 요청마다 프롬프트 이력을 남기고 실제 이미지·편집·렌더 측정값과 결과만 연결한다.

음악 한 곡을 주고 M/V 전체 제작을 요청하면, 곡 분석→장르·분위기에 맞는 연출→전곡 스토리보드→필요한 시트와 장면 이미지→Showreel 편집·검수·납품을 한 요청 안에서 수행한다. 아이돌·군무는 선택 가능한 연출이며 기본 형식이 아니다. 지원 장르를 고정 목록으로 제한하지 않고 세부·혼합·미분류 스타일도 실제 음악 특성과 요청으로 해석한다.

시작 시에는 [사용 시 업데이트 확인](../road-music-skills-update/references/use-time-check.md)을 한 번만 적용한다.

결과물은 전곡 MP4, `reel/` 또는 원본을 연결한 편집 프로젝트, 스토리보드·전체 이미지 프롬프트·원본 자산·타임라인·QA다. 가사 자막이 있으면 SRT도 납품한다. 기본 LTX, 긴 하네스, 고정 장수 보드/애니매틱은 쓰지 않으며 LTX는 사용자가 명시할 때만 연결한다.


신규 음원 제작과 비트·모션·가사 싱크 수정은 [비트·모션·가사·섬광 품질 절차](references/production-quality.md)를 먼저 읽고 적용한다. 구간별 강세가 부족하면 동봉 `scripts/audio_onsets.py`로 실제 소리의 로컬 변화를 보강해 장면 코드까지 연결하고, 가사 정렬의 근거·불확실성, 역순 시크, 최종 섬광·전곡 QA를 함께 확인한다. 기존 표시 선택·원문·원곡 시계는 유지한다. 기술 검사와 음악·미술 적합성을 따로 판정하고, 약한 구간은 실제 이동·착지·정착과 가사 소재의 조형 변화를 원음 proof로 보완한다. 큰 활자의 대비·범위와 연속 효과의 구간 경계도 확인한다.

## 프로젝트 저장공간

작업 시작·수정·완료의 저장공간은 [저장공간 운영 스킬](../road-music-storage/SKILL.md)을 함께 적용한다. 새 M/V의 제작 입력·프레임·재개 자료는 `.roadmusic/work/<원음SHA12>/<프로젝트--ID>/`에 두고, `Output`에는 검증·게시된 최종 납품의 시간 버전만 둔다. 원음·완성본·승인 자산·편집 소스를 보존하고 프로젝트별 `.roadmusic/cache`와 중간본·상세 이력을 분리한다. 기존 자료는 임의 이동·삭제하지 않고 등록된 항목의 보호 사유·미리보기를 확인한다.

## 이미지 모델·유료 사용 경계

기본 이미지 생성은 **ChatGPT/Codex의 내장 `image_gen`, 로컬 Claude Code CLI/IDE의 `gpt-image` ChatGPT 로그인 Codex CLI 브리지, 또는 Antigravity의 내장 Nano Banana 이미지 기능**만 사용한다. Antigravity에서는 현재 버전이 제공하는 네이티브 도구/`image-generator` 경로를 확인하며, 추론 모델을 이미지 모델로 바꾸지 않는다.

`gpt-image-2.5` 등 별도 과금되는 API/모델은 **사용자가 해당 작업에 별도로 유료 모델/API 사용을 명시적으로 요청한 경우에만** 사용한다. “고품질로”, “알아서”, “GPT 이미지”, 모델명 비교·인용·사용 금지는 유료 사용 승인이 아니다. 생성 실패·한도·도구 미지원·참조 수 부족을 유료 API 자동 전환으로 해결하지 않는다.

제작 계획의 기본 정책은 `allowPaidModels:false`다. 별도 유료 요청이 있을 때만 모델·요청 범위를 기록하고 그 범위에서 적용한다. 호스트 기능이 없거나 한도에 걸리면 해당 단계의 제한을 보고하고 이미지/프로젝트를 보존한다.

## 호스트별 이미지 도구

ChatGPT/Codex에서는 내장 `image_gen`, 로컬 Claude Code CLI/IDE에서는 실제로 읽은 `gpt-image` 스킬의 ChatGPT 로그인 Codex CLI 브리지를, Antigravity에서는 현재 세션의 네이티브 이미지 생성 기능 또는 내장 `image-generator` 경로를 사용한다. [공통 이미지 계약](../road-music-video-studio/references/image-providers.md)을 따른다. `image_gen` 전용 인자는 ChatGPT 경로이며 Claude의 브리지 인자와 Antigravity 도구명·모델 옵션을 추정하지 않는다. 새 M/V는 선택한 호스트 도구의 실제 장면 자산·전용 썸네일·ledger·decode·렌더 사용 증거가 있어야 한다. 원음 시계와 승인 가사 시계를 바꾸지 않는다. 사람이 이미지 미사용 또는 제공·승인 자산 재사용을 명시한 경우만 예외다. Claude에서 `gpt-image`가 없거나 선택 모델/도구가 없으면 해당 단계는 blocked로 남기며 설치·인증·유료 API·절차형 코드 대체로 우회하지 않는다. 실제 파일·도구·반환 모델을 기록하고 동일한 자산 검수/렌더 계약으로 전달한다.

## HTML 제작·검수 화면
HTML을 사용하는 단계에서는 [단계별 페이지 열기](../road-music-video-studio/references/page-flow.md)에 따라 필요한 화면을 Ego 브라우저에서 실제로 열어 확인한다. 이미 저장한 선택을 다시 묻거나 같은 화면을 불필요하게 다시 로드하지 않는다.


실제 영상 제작은 [공통 HTML 영상 제작실](../road-music-video-studio/SKILL.md)을 함께 사용한다. 스타일과 음악을 보고·들으며 고르고, 기획/이미지·부분 영상·최종 결과·수정 의견을 같은 프로젝트에 등록한다. 제작 설정은 `/`, 완성 결과의 탐색은 `/works/`와 음악별 상세로 나누며 상세의 내부 메뉴에서 영상·가사/SRT·스토리보드·의견을 확인한다. 설명은 [Markdown 가이드](../road-music-video-studio/assets/guides/start.md)를 먼저 수정한 뒤 HTML로 생성하며 각 화면에서 해당 가이드와 Markdown 복사를 제공한다. `publish`는 검수 등록 전체를 manifest로 교체하므로, 후속 게시에서도 유지할 기존 스토리보드·음원·영상·자막을 모두 manifest에 다시 넣는다. 이미 받은 선택은 유지하고 저장된 selection.json/feedback.json을 실제로 읽어 이 스킬의 입력에 반영한다. 표시용 페이지 생성이나 버튼 저장을 렌더 완료로 보고하지 않는다. HTML은 제작·검수 인터페이스이며, 엔진별 실제 생성·편집·렌더와 원곡/가사 시계는 아래 절차가 맡는다.

## 범위와 입력 권한

- 기존 통과 음원·가사·자산 중 이번 곡과 연출에 맞는 것을 재사용한다. 가사 원문과 기존 자산은 덮어쓰거나 임의 개사하지 않는다. 지난 M/V의 인원·공간·샷 수·글꼴·팔레트를 다음 곡에 자동 적용하지 않는다.
- 음악만으로 전체 제작을 맡긴 요청에는 연출·스토리보드·필요한 가상 인물/스타일·배경·소품 시트와 장면 이미지의 생성도 포함된다. 없는 key를 호스트별 이미지 생성 도구로 만들고 실물 검수→key-ready→장면 생성으로 계속하며, 내부 검수를 사용자 재승인 대기로 바꾸지 않는다. 기획만·검토만·스킬 수정 요청에는 실제 이미지/영상 생성을 시작하지 않는다.
- 가사가 없으면 인접한 확정 가사 자료나 기존 ASR 런타임을 확인한다. ASR 초안·불확실한 구절은 확정 원문과 구분하며 가사를 지어내지 않는다. 연주곡은 가사/가라오케를 만들지 않는다. 정확한 자막 자료가 없다는 이유로 가능한 영상 기획·제작 전체를 멈추지 말고, 필수 자막 요건을 충족하지 못하면 그 항목을 명확히 보고한다.
- 곡 선택을 위임받으면 새 음악을 생성하지 않는다. 곡명·절대 경로·가사/사용 권한을 작은 입력 카드에 고정한다.
- 화보·영화·공연 참고 자료에서는 구도·빛·깊이·리듬을 관찰한다. 실존 얼굴·의상·세트는 복제하지 않는다. 새 음악 생성·설치·유료 API·외부 게시 권한은 M/V 제작 위임에서 추정하지 않는다.

## 네이티브 Showreel과 도구 상태

실제 제작·렌더·QA 때만 `$SHOWREEL_HOME/SKILL.md` 또는 `$HOME/.local/share/roadmusic-video-tools/showreel/SKILL.md`를 찾고 설치본의 `SKILL.md`와 `references/`의 `engine.md`, `design.md`, `techniques.md`, `qa.md`를 읽는다. 없으면 계획을 보존하고 대체 엔진으로 바꾸지 않는다. 스킬 유지보수는 이 파일과 직접 참조만 읽는다.

설치본의 `new_project.py`, `render.mjs`, `contact_sheet.py`, `qa_check.py`를 사용하며 렌더러를 재작성하지 않는다. 실제 FFmpeg 호환 오류만 근거·버전·diff·재QA가 있는 local wrapper/최소 수정으로 해결할 수 있다. 렌더러는 하나만 실행한다.

완성본의 오프닝 길이·무음 같은 부분 수정은 기존 네이티브 렌더와 FFmpeg 마감 편집을 재사용할 수 있다. 변경된 구간만 재처리하고, 보존한 본편은 프레임·음원·자막의 대응 관계를 검증한다. 원본 `reel/`을 남긴 파생 편집은 원본 프로젝트와 최종 편집표의 역할을 구분해 기록한다. 오프닝 부분 수정에는 [오프닝 지침](references/opening-thumbnail.md)의 시간 매핑·오디오 검증을 적용한다.

Node·ffmpeg·Chrome와 Python 경로를 단계별 확인한다. 기본 `python3` 실패 뒤 local venv/bundled Python의 NumPy/Pillow를 찾아 하나를 고정하고 이후 Python 도구에 일관되게 쓴다. legacy preflight의 성공 문구는 충분한 증거가 아니다. 미설치 도구는 의존 단계만 보류하고 시트·보드·검수 같은 독립 작업은 계속한다. Claude Code의 이미지 단계에는 로드된 `gpt-image`가 필요하며, Codex/Antigravity의 실제 네이티브 이미지 기능은 그 외부 스킬과 독립적이다. 사용자가 별도로 해당 유료 모델/API의 사용을 명시적으로 요청한 경우에만 `gpt-image-api`를 읽어 적용하며, 일반 “GPT 이미지”는 API 권한이 아니다.

## 5단계 제작

1. **곡 분석과 연출** — 절대 음원 경로·가사 유무·비율·목적·사용 가능 자산을 기록한다. 신규 전곡 제작은 [음악별 연출과 스토리보드](references/music-direction.md)를 읽고 리듬·에너지·음색·가창·가사의 정서·곡 구조를 근거로 연출과 인물/군무 필요 여부를 정한다. `ffprobe`로 원곡 길이를 확인하고 오프닝·구간 편집을 포함한 최종 출력 종료 시각 `T`에서 `frames=ceil(T×fps)`, `renderDuration=frames/fps`를 계산한다. 직접 제작은 `new_project.py --duration`, `project.json`, `REEL.config`를 일치시킨다. 파생 편집은 원본 설정을 보존하고 최신 편집 프로젝트·편집표·출력 길이를 일치시킨다. 원곡 끝을 자르지 않으며 마지막 프레임 패딩과 실제 음악 끝을 구분한다.
2. **스토리보드와 자산 기준** — 도입부터 끝까지 시간대별 음악 사건·장면 의도/행동·인물/공간·거리/각도·필요 key·이미지 prompt ID·카메라/효과·전환·자막을 통합 보드에 연결한다. 사진의 장소만 바꾸는 대신 서사·감정·시각 모티프가 전개되게 한다. 인물·군무가 필요 없는 곡은 스타일/공간/소품 기준만 잡는다. 기존 key의 실제 모습과 사용 범위를 확인하고 `superseded`/`user_rejected`와 key-ready를 구분한다. 거절된 샷 배치를 재사용하지 않되 허가된 정체성·소품·공간 기준은 재사용할 수 있다.
3. **시트와 장면 이미지** — 별도의 유료 API 사용 요청이 없으면 호스트별 기본 이미지 생성 도구로 필요한 key부터 생성·검수하고, 해당 key를 참조한 단일 full-frame 대표 장면을 만든다. 통과한 기준으로 보드의 나머지 독립 샷을 도구가 허용하는 범위에서 묶어 생성한다. 인물이 있으면 [자연스러운 이미지 결합](references/natural-image.md)을 적용하며, 반복 슬롯은 확대·반전·색 변경이 아닌 새 행동·구도·대형·공간·렌즈의 원본으로 채운다. 전곡 shot별 자산·해시·등장 간격·반복 이유와 실제 사용한 프롬프트/참조 계보를 보존한다. 새 전곡 M/V는 사용자가 생략을 원하지 않으면 [오프닝 썸네일](references/opening-thumbnail.md)을 함께 기획한다. 인물 없는 작품은 장면·소품·추상 모티프를 표지로 쓸 수 있으며, 제목·아티스트·제작 크레딧은 확정된 항목만 표기한다.
4. **Showreel 편집** — `timeline.js`의 가창·박·히트에 장면, 카메라, 화면효과, 자막을 연결한다. 설치 Showreel의 표현력으로 짧은 원음 시퀀스를 먼저 완성한다. 경량화는 절차를 줄이는 것이며 연출을 약하게 만드는 이유가 아니다. 계획한 M/V 장면을 기본 화면으로 두고 타이포·스펙트럼·리본·전환·화면 회전/줌/진동을 구간별로 선택해 들어왔다가 빠지게 한다. 연출표의 카메라·이펙트명은 실제 `render(t)` 분기로 연결하고, 미지원 값이 조용히 정지 기본값으로 빠지지 않게 장면별 동작 매핑을 검증한다. 사용자가 상시 스펙트럼을 요청하면 한쪽/하단의 지속 레이어를 따로 두고 실제 대역값으로 형태를 변화시킨다. 오프닝 썸네일은 본편 자막과 독립된 시간 구간으로 두며, 표지가 완전히 퇴장하기 전에는 가사 glyph가 보이지 않게 한다. 오프닝 길이·무음 여부는 최신 요청을 따르고, 길이를 늘이거나 줄일 때는 원음, 자막, 비트, FFT, 장면의 시간 대응을 함께 갱신한다. 거대 문구를 매 구절에 강제하거나 인물을 피하려고 고정 영역으로 잘라 가려진 글자를 유지하지 않는다. 짧은 의도적 겹침은 허용하고 장시간 장면을 덮는지 실제 재생으로 판단한다. DOM·캐시는 `setup`, `render(t)`는 순수 시간 함수로 갱신한다. 하드 컷은 `cue - 0.5/fps`, 최종 `--sub 4`를 고려한다. 단어 timestamp가 있을 때만 단어 동기화를 주장한다. [리듬과 화면·타이포](references/rhythm-typography.md), 노래 자막의 [가창 타이밍](references/vocal-caption-timing.md)을 적용한다.
5. **폰트·QA·납품** — 최신 글꼴 지정·해제와 첨부 스타일을 따른다. 특정 자막 스타일의 전곡 통일 요청이면 서체·굵기·크기·색·획·그림자를 고정하고 구간별 다양화를 강제하지 않는다. 글꼴 선택을 위임받으면 곡과 구간에 맞는 확인된 OFL 서체·색·획·재질·타이포 모션을 함께 설계하고, 이전 Paperlogy 지정을 영구 기본값으로 굳히지 않는다. 명시된 서체는 workspace 실파일·`fonts.css`·OFL을 확인하고, 없으면 공식 파일 확보를 시도한다. 실패 시 폰트 의존 최종 단계만 보류하며 조용히 대체하지 않는다. 대표 스틸/strip과 원음 proof에서 오프닝 중 glyph 0, 효과의 임팩트, 자막 선행 여부를 확인하고 약한 구간을 고친다. 독립 대표 아트 검토 후 native proof와 전곡 렌더·전체 컨택트시트·경계 strip·`qa_check.py`로 시각 QA를 마치고 MP4·`reel/`·타임라인·QA를 보존한다. 최종 시트는 고유 컷 커버리지, 반복 자산 목록과 원인을 함께 검토한다.

## 통과와 보고

선택한 미술 양식에서 인물-공간의 원근·지지·그림자·광원/반사·소품 상호작용을 검수하고, 인물 없는 작품은 공간·물성·모티프의 일관성을 본다. 전체 섬광은 초당 3회 이하로 둔다. 보고에는 장르/연출 선택 근거, 절대 경로, 재사용/새 key, 스토리보드·프롬프트, 사용 도구·글꼴, 실제 렌더/QA 결과와 자막·청취 검증 범위, shot별 자산/해시·반복 이유를 적는다. 최종 MP4·해당하는 SRT·포스터·검토 페이지·편집표·크레딧의 버전을 일치시키고, 원본과 파생 편집이 다르면 최신 진입 파일을 명시한다. 음악·Showreel·생성 도구가 실제로 없으면 의존 단계만 보류하고 가능한 작업은 계속한다. 가사 없는 연주곡을 미완료로 취급하거나, 기술 검사만으로 모든 장르의 품질을 보증하지 않는다.

HTML 제작·선택·검수 화면에는 [공통 DESIGN.md](../road-music-video-studio/assets/design/DESIGN.md)와 번들 Paperlogy를 적용한다. 현재 프로젝트의 DESIGN.md가 있으면 이를 먼저 대조한다. 화면 열기는 [단계별 페이지 이동](../road-music-video-studio/references/page-flow.md)의 같은 Ego 페이지를 재사용하며, 이미 열린 화면에 새 탭을 추가하지 않는다.

완성 결과는 [공통 보관함 계약](../road-music-video-studio/SKILL.md#음악별-내-작업물과-상세)에 따라 원음 기준으로 등록한다. 음악별 상세의 내부 메뉴에서 스타일 영상·음원·가사/자막·스토리보드·검수 기록을 함께 확인하고, 실제 확인된 스타일 이름을 manifest에 기록한다. `reel/` 연결 자료, 타임라인·프롬프트·QA처럼 허용된 제작 증빙은 [결과 등록 계약](../road-music-video-studio/references/result-contract.md)에 따라 감상용 ZIP과 분리한 제작자료 ZIP에 등록한다. 전역 메뉴에 결과·검수 페이지를 추가로 분산시키지 않는다.
