# 음악을 화면 사건으로 연출하기

가사의 단어를 바꾸는 화면이 아니라, 음악과 가사에 따라 **대상·행동·공간이 전개되는 작품**을 만든다. 기본 Showreel의 콘셉트 비교·구간별 아트 디렉션·직접 장면 구현·실제 영상 비평을 기본 제작 방식으로 사용한다. 음악 전용 기능은 원곡·가사·시계·표시·다곡 연결을 지키는 기반이며 화면 표현의 목록이 아니다.

## 경로 선택

- **일반 음악 모션그래픽은 개방형 native 연출이 기본**이다. [음악 연출](references/music-direction.md) → [이미지 역할](references/image-direction.md) → [실제 제작](references/production.md) 순으로 필요한 부분을 읽는다. 스타일 이름이나 네 가지 direction enum부터 고르지 않는다.
- 사용자가 CD·그루브 다이얼·리듬 캔버스·등록 프리셋을 **명시**했으면 [프리셋 모드](references/preset-mode.md)를 따른다. 기존 선택·화면·명령을 보존한다.
- 기존 프로젝트 수정은 저장된 원곡/가사/표시와 요청 범위를 유지한다. 기존 결과를 새 경로로 몰래 바꾸거나 덮어쓰지 않는다.

현재 설치된 기본 Showreel `SKILL.md`와 `references/brief.md`, `design.md`, `engine.md`, `techniques.md`, `qa.md`를 읽고 실제 API를 사용한다. DOM/SVG/Canvas/WebGL/3D/물리/사진 합성은 콘셉트에 맞춰 선택한다. T01–T22는 코드 참고자료이며 자동 효과 enum이나 모두 넣을 체크리스트가 아니다. 기본 설치/도구 경로는 [제작 절차](references/production.md)에 있다.

생성하는 HTML UI와 템플릿은 저장소 `DESIGN.md` 토큰과 번들 Paperlogy를 사용한다. 영상 장면의 팔레트·재질·타임라인은 곡의 연출 계약을 유지한다.


HTML을 사용하는 단계에서는 [단계별 페이지 열기](../road-music-video-studio/references/page-flow.md)에 따라 필요한 화면을 Ego 브라우저에서 실제로 열어 확인한다. 이미 저장한 선택을 다시 묻거나 같은 화면을 불필요하게 다시 로드하지 않는다.

ChatGPT/Codex에서는 내장 `image_gen`, 로컬 Claude Code CLI/IDE에서는 실제로 읽은 `gpt-image` 스킬의 ChatGPT 로그인 Codex CLI 브리지를, Antigravity에서는 현재 세션의 네이티브 이미지 생성 기능을 사용한다. [공통 이미지 계약](../road-music-video-studio/references/image-providers.md)을 따른다. 이미지가 필요한데 해당 도구가 없으면 의존성 누락을 보고하고 유료 API로 대체하지 않는다. 이미지 없는 절차형 연출은 이 의존성이 필요 없다.

## 제작 흐름

1. **현재 음악을 고정한다.** 실제 파일·해시·길이와 승인 가사·시각의 출처를 확인한다. 장르/편성/감정은 사용자 정보·메타데이터·분석·청취/추론을 구분한다. [표시 네 항목](references/playlist.md)은 미응답만 묻고 기존 답은 유지한다. `native_project.py prepare`는 style 없이 원음·PCM 샘플 시계·가사·분석·FFT를 준비한다. 준비 완료가 미술 완료는 아니다.
2. **작품의 생각을 고른다.** 새 전곡 연출을 위임받으면 서로 다른 콘셉트 후보를 비교한다. 이미 확정한 안/좁은 수정에 후보를 재요구하지 않는다. 가사의 화자·관계·구체적 소재·행동·감정 변화를 읽고, `무엇이 → 어떻게 변하며 → 어떤 공간/다음 화면이 되는가`를 설계한다. 장르별 기본 색/가수/카페/네온이나 지난 곡의 열차·별·리본을 답으로 고정하지 않는다.
3. **이미지가 장면에서 할 일을 정한다.** 새 음악에는 필요한 장면 자산과 전용 썸네일을 기본 내장 `image_gen`으로 만든다. 장소, 움직이는 오브젝트, 마스크, 글자 질감, 패럴랙스 층, 콜라주 조각처럼 실제 역할을 설계한다. 이미지 수·사진 비중·인물 사용을 고정하지 않는다. 순수 기하/제공 이미지/재사용을 명시하면 그 선택이 우선한다. 생성 근거와 실제 화면 사용 근거를 나눈다.
4. **열린 장면 계획을 실제 코드로 만든다.** [composition/media 계약](references/composition-contract.md)을 작성해 `native_project.py apply`로 연결한다. 먼저 핵심 스타일 프레임과 새로운 기술 과제를 시험하고, 약한 방향을 고른 뒤 전곡 장면을 확장한다. `REEL.scene`을 직접 작성하며 helper가 가사 의미나 임의 효과 이름을 자동 실행한다고 설명하지 않는다. [표현력 연결](references/showreel-motion.md)을 참고한다.
5. **음악·가사 적합성을 실제 영상으로 판정한다.** [미술/의미 검수](references/native-qa.md)에서 장면별 유지·고침·다시 만듦과 최약 구간을 기록한다. 단어·스펙트럼을 제외해도 대상/상태/공간이 전개되는지, 이미지가 실제 의미·재질·깊이에 기여하는지 본다. 원음 proof·동작 띠·경계·독립 검토로 약한 장면을 다시 만든다. 기술 점수나 효과 개수로 미술 판정을 대신하지 않는다.
6. **전곡으로 마감한다.** 현재 입력과 일치하는 runtime 검사와 실제 creative review 후 native 렌더·믹스·전체 길이/디코드·규격·음량·섬광을 검수한다. 최종 실제 시트를 열어보고 `finalize`로 출력·검토 기록을 대조한 뒤 영상·공유용·SRT·타이밍/설정·편집 프로젝트·이미지 근거·검수 범위를 납품한다. 짧은 proof를 전곡 완료로 보고하지 않는다.

## 음악 전용 불변식

- 사용자 원곡과 승인 가사를 임의로 편집·개사하지 않는다. 영상은 원곡 0초 시계, 여러 곡은 실제 PCM 샘플 합으로 연결한다. 선택 컷의 장면/분석도 원곡 시각에서 매핑한다.
- 전문 가사는 `[start,end)`부터 읽히는 별도 레이어다. 장식 타이포의 조립/입자/마스크로 본문을 늦게 드러내지 않는다. 미리보기는 원시 cue 시각, subframe export는 현재 출력 target frame의 문구를 유지해 두 구절이 한 프레임에 섞이지 않게 한다. 입력 cue/SRT·음악/장면 시계는 이동하지 않는다. 실제 단어 시각 없이 가라오케·음절 싱크를 주장하지 않는다. [가창 입력](references/captions.md)과 [기술 품질](references/production-quality.md)을 유지한다.
- 썸네일은 독립 납품 자산이다. 이미 지정한 첫 `[0,0.5)` 카드 선택은 유지하고, 새 오프닝은 곡의 시작과 사용자 요청에 맞춰 계획한다. 고정 카드를 합성해도 음악/가사/총길이를 밀지 않으며 중간 구간 proof에 다시 붙이지 않는다.
- 분석값은 beats/downbeats/hits/energy/실제 FFT의 근거와 한계를 구분한다. 필요하면 `audio_onsets.py`로 로컬 강세를 보강하고 실제 장면에 연결한다. 정적 포스터를 보완하려고 모든 박에 점멸·줌을 반복하지 않는다.
- 시간은 순수 함수다. 필수 이미지 decode, 폰트·글자 범위, 역순 탐색, 원곡/가사/자산 해시를 확인한다. 코드·자산·폰트가 바뀌면 이전 runtime/creative 증거를 재사용하지 않는다.
- 렌더러는 한 번에 하나. 기존 설치를 재사용하고 새 엔진/모델·유료 API·새 음악·나레이션·외부 게시·정식 배포를 제작 요청에 포함된 것으로 추정하지 않는다. 실제 청취/신규 ASR/연속 재생 여부를 그대로 보고한다.

HTML 제작·선택·검수 화면에는 [공통 DESIGN.md](../road-music-video-studio/assets/design/DESIGN.md)와 번들 Paperlogy를 적용한다. 현재 프로젝트의 DESIGN.md가 있으면 이를 먼저 대조한다. 화면 열기는 [단계별 페이지 이동](../road-music-video-studio/references/page-flow.md)의 같은 Ego 페이지를 재사용하며, 이미 열린 화면에 새 탭을 추가하지 않는다.
