# 가창 자막과 시계

현재 테이크로 다시 정렬하거나 ASR 반복·환각을 보완할 때는 [원음·정렬 근거와 최종 검증](production-quality.md)을 함께 적용한다. 겹치는 짧은 구간의 근거와 cue별 불확실성을 남기며, 자동 정렬 상태를 청취 검수 완료로 승격하지 않는다.

비트·음량·글자 수는 가창 onset 근거가 아니다. 승인 가사가 있으면 원문·띄어쓰기·줄 순서를 보존한다. MP3만 있으면 로컬 ASR로 **초안**을 만들고 가사 원문과 시각 검수 여부를 따로 기록한다.

## 입력

```json
{"schemaVersion":1,"status":"auto-asr-unreviewed","source":{"path":"/절대/원곡.mp3","sha256":"실제원곡해시","cutStartSeconds":0},"cues":[{"id":1,"startSeconds":14.25,"endSeconds":18.7,"text":"사용자의 가사 원문","status":"auto-asr-unreviewed"}]}
```

`source.cutStartSeconds`는 자막 0초가 원곡 몇 초인지다. 전체 자막=0, 원곡 79.76초에서 자른 음원을 인식한 상대 자막=79.76. 실제 원곡 해시를 넣는다. SRT는 별도 출처와 원점을 남긴다. 기존 프리셋 CLI는 `--caption-origin`, native의 상대 SRT는 `--playlist`의 해당 track `captionOriginSeconds` 또는 source.cutStartSeconds를 기록한 JSON을 사용한다. native prepare에 없는 `--caption-origin` 플래그를 전달하지 않는다.

변환은 `표시초 = 입력큐초 + captionOrigin - 음악cutStart`. 겹치는 큐만 남기고 양끝 절단을 표시한다. 원문은 바꾸지 않는다. 역전/겹침/NaN/빈 cue는 거부한다. native는 원문의 개행을 보존해 두 줄 안전 영역에서 표시한다. 기존 한 줄 CD 템플릿은 개행을 거부하므로 원문을 임의로 합치지 말고 해당 형식의 가창 경계를 검토한다. 단어 시각 없는 문장을 가라오케 동기라고 부르지 않는다.

## MP3만 있을 때

기존 whisper.cpp/정렬 런타임과 모델 캐시를 찾고 도움말을 확인한다. 이 기기에서 확인된 실행 파일은 `/opt/homebrew/bin/whisper-cli`, 캐시는 `~/.cache/whisper-models/ggml-large-v3-turbo.bin`이다. 버전·파일을 다시 확인하고 사용한다. 새 모델 다운로드나 유료 ASR 전송은 자동 대안이 아니다.

기존 whisper.cpp 1.9.5와 turbo에서는 `-m <모델파일> -dtw large.v3.turbo -nfa -l ko -ojf`를 사용하고 실제 로그의 dtw=1/flash attn=0을 확인한다. 다른 버전에서는 그대로 추정 적용하지 않는다. 실제 정렬 WAV는 16k mono PCM으로 만들고 원곡/WAV 해시와 offset을 고정한다.

`tokens[].t_dtw/100 + 원곡offset`은 ASR가 인식한 토큰의 대략적 위치다. 승인 가사 강제 정렬이나 한국어 음절 정확도를 뜻하지 않는다. 일반 offsets와 단위를 혼용하지 않는다. 근거: [whisper.cpp CLI](https://github.com/ggml-org/whisper.cpp/blob/d1be6fde11ac6e0407606b4e42fe72d34add8037/examples/cli/cli.cpp), [API](https://github.com/ggml-org/whisper.cpp/blob/d1be6fde11ac6e0407606b4e42fe72d34add8037/include/whisper.h).

segment 앞 반주/숨을 곧 가창 시작으로 쓰지 않는다. 누락/음차/환각으로 첫 단어가 사라졌다면 중간 토큰을 첫 발성으로 확정하지 않는다. 두 문장이 긴 segment에 합쳐졌으면 뒤 문장을 미리 띄우지 않는다. 실제 첫 토큰, 가창 신호/기존 정렬 결과, 원음 포함 짧은 proof를 교차 확인한다. 보컬 분리/파형은 보조 근거다. 승인 가사를 ASR 문구로 교체하지 않는다.

### DTW 어절 매핑 검수

whisper.cpp 1.9.5의 `t_dtw`는 토큰 종료측 경계로 다룬다. 첫 토큰이나 첫 UTF-8 조각의 종료를 발성 시작으로 복사하지 않는다. JSON의 UTF-8 병합이 내부 마지막 조각 시각을 잃었다면 raw 토큰을 보존한 출력으로 대조한다.

- UTF-8 조각은 문자가 완성된 마지막 byte-token의 경계로 합친다. 공백으로 앞 어절을 확정할 때는 **현재 공백 토큰 시각을 대입하기 전** 앞 어절의 마지막 lexical 경계를 사용한다. 다음 어절 시각이 앞 어절 끝에 들어가지 않는 회귀 예제를 둔다.
- 각 어절 종료가 실제 매핑한 마지막 글자의 DTW 경계와 같은지 확인한다. 문장 사이 무음을 앞 어절 끝까지 늘이지 않는다.
- 모든 어절에 `start <= firstFragmentEnd <= wordEnd`를 검사한다. 이 검사는 모순을 거를 뿐 가창 정확도를 증명하지 않는다. 앞 어절 종료를 다음 어절 시작으로 복사한 값도 실제 발성 확인과 구분한다.
- 혼합음의 spectral flux는 반주 타격음을 고를 수 있다. 탐색 창·후보 거부 기준·미확정 목록을 기록하고, peak prominence를 보컬 검출 신뢰도로 부르지 않는다. 미확정 시작점은 추정 상태로 남기며 자동 결과를 청취 확정본으로 승격하지 않는다.

인식 도구가 없으면 이미지/영상 제작은 계속하되 동기 자막을 임의 생성하지 않고 누락 의존성과 검증 범위를 보고한다.

## 싱크 확인

구절 onset/end·원문·근거 파일/시각·신뢰도·수정 전후를 남긴다. 전역 offset은 일정 지연이 실측됐을 때만 사용한다. 특정 문장 문제는 반복 구절도 각각 점검한다. 소폭 선행 요청은 추정 앵커와 표시 시각을 구분해 기록한다.

템플릿은 `[start,end)`에서 문장 전체 opacity=1이다. 조립/마스크/페이드로 전문이 늦게 읽히지 않게 한다. 영상 하드컷 반 프레임 보정은 자막 onset에 적용하지 않는다. 인트로 변경에도 음악·자막의 원곡 시계는 보존한다.

`render.mjs --sub 4 --shutter .5`의 최종 프레임은 프레임 중심 주위의 네 화면을 평균한다. native 본문 자막은 이 평균 중에도 해당 **target output frame**의 `[start,end)` cue 하나를 고정해 이전·다음 구절의 글리프가 섞이지 않게 한다. 일반 미리보기와 raw seek는 입력 cue의 원시 `[start,end)` 시계를 그대로 사용한다. 따라서 0.62초 cue는 30fps 출력에서 첫 target frame `ceil(0.62×30)/30`부터 보이며, SRT·JSON cue 시각 자체를 반 프레임만큼 옮기지 않는다.

도입·각 후렴·긴 무음 전후의 원음 포함 proof, 시작 직전/직후 번인 프레임, SRT 일치, 마지막 음절 전 퇴장 여부를 본다. JSON 유효성은 청취/원문 검수가 아니다. `draft` 상태를 검수 없이 승격하지 않는다.


## 그루브 다이얼 어절 강조

어절 추적이 필수인 요청은 `plan --require-word-timing`으로 `wordTiming.required:true`를 저장한다. `create --plan`은 이를 상속하고, 계획 없이 호출하면 `create --require-word-timing`을 쓴다. 지원하지 않는 프리셋이나 화면에 보이는 가창 큐의 누락된 `words`는 출력 폴더를 만들기 전에 거부한다. 일반 줄 자막 요청은 이 옵션 없이 기존대로 제작한다.

보컬 전 인트로처럼 표시 가창 큐가 0개인 구간은 허용한다. 이때 `wordTiming.visibleCueCount:0`은 그 구간의 검증 범위이며 가창 정렬 완료가 아니다. 곡별 계획만 필수인 혼합 플레이리스트는 해당 `playlist.json.tracks[].wordTiming`만 확인하고 다른 곡의 요구로 확대하지 않는다.

가창 정렬 결과를 같은 원곡 시계의 `cues[].words`에 넣는다. 문장 표시 구간과 실제 어절 구간은 별개이며 쉼 구간을 어절에 강제로 늘려 붙이지 않는다.

```json
{"startSeconds":10,"endSeconds":14,"text":"낡은 사진","words":[{"text":"낡은","startSeconds":10.3,"endSeconds":11.1},{"text":"사진","startSeconds":11.2,"endSeconds":12.5}]}
```

words의 text를 공백 없이 합친 값은 cue 본문과 일치해야 하며, 어절은 문장 범위 안에서 순서대로 겹치지 않아야 한다. 각 어절에도 원곡 cut/origin/플레이리스트 offset을 동일하게 적용하고 컷에 걸친 시각만 자른다. 단어별 provenance·초안 상태는 보존한다. 글자 수에 따른 균등 배분·줄 길이에 맞춘 시간 재조정은 하지 않는다. SRT처럼 어절 시간이 없으면 문장만 읽기 좋게 표시한다.

Whisper 추정 시각과 실제 가창 청취 검수를 구분한다. 비트는 확대·기울기의 크기만 바꾸며 어절의 시작/끝·원문·SRT 시각을 바꾸지 않는다. 등록 미리보기의 ASR 초안을 새 곡의 가사 정답이나 100% 싱크 보장으로 사용하지 않는다.


## 원문이 있어도 인식이 맞지 않을 때

원곡과 원문 출처를 먼저 확인한다. 같은 제목의 다른 모델·다른 테이크를 길이만으로 같다고 판단하지 않는다. 확인 가능한 원 WAV/FLAC가 있다면 도입 이후·중간·후반의 파형 상관과 지연을 비교해 동일 연주 근거를 남긴다.

Whisper가 ‘자막 제공’ 같은 반주 환각을 반복하거나 실제 원문과 다른 문장을 출력하면 그 문자열을 가사로 쓰지 않는다. 원문과 일치하는 구절·시각만 부분 자막으로 남기고 상태를 `partial-auto-asr-unreviewed` 등으로 표시한다. 불명확한 나머지는 전문 원문과 누락 사유를 별도 저장한다. 원문이 있다는 이유로 전체 시간에 균등 배분하거나 ASR 프롬프트를 강제 정렬 완료라고 부르지 않는다. 어절 경계 근거가 없으면 words를 만들지 않는다.

가창 싱크가 요청의 필수 결과인데 일부만 확인됐다면 제작 보고에서 그 미완료 범위를 먼저 알린다. 영상의 정상 렌더나 두 ASR 문구의 일치를 실제 가창 청취 검수로 확대하지 않는다. 다른 정렬 모델 설치/음원 교체는 기존 설치·원곡 보존 경계에 따라 별도로 처리한다.

주황색 진행 추적을 유지하라는 요청에는 `create` 응답과 production.json의 `wordTiming`(전체 cue/강조 타이밍 cue/강조 단위 수)을 확인하고 짧은 가창 구간의 실제 번인 영상을 검사한다. words 누락을 표시 옵션 SKIP으로 간주하거나 흰 문장만 있는 영상으로 조용히 대체하지 않는다. 이 수치는 타이밍 데이터 존재 여부이며 실제 음성 정답률이나 청취 검수 결과가 아니다.
