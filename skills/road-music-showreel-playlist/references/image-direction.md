# 생성 이미지를 장면의 재료로 쓰기

Codex의 기본 생성/편집은 내장 `image_gen`과 imagegen 스킬이다. 새 음악에는 콘셉트에 필요한 장면 자산과 전용 썸네일을 생성한다. 순수 기하·제공 이미지·승인 자산 재사용 선택은 우선한다. 다른 호스트의 이미 명시된 이미지 어댑터는 그 환경의 지침을 확인하되 요청 없이 새 유료 API/모델로 바꾸지 않는다. 이미지 도구가 없으면 해당 단계를 미완료로 남긴다.

## 프롬프트보다 역할을 먼저 정한다

장면 계획에서 다음을 정한 뒤 생성한다: 가사/음악의 근거, 자산이 담당하는 대상/공간/재질, 등장·변화·전환에서 쓰는 방법, 실제 화면 크기/크롭/안전 여백, 다른 자산과의 색·광원·시점 관계.

| 역할의 예 | 실제 장면에서 할 수 있는 일 | 확인할 것 |
|---|---|---|
| 공간/환경 plate | 창/통로 안의 다음 공간, 깊이 레이어 | 가려졌다 열리는 공간이 장면 의미에 기여하는가 |
| scene object | 종이·꽃·기기·소품 자체의 이동/접힘/변형 | 바깥 배경과 분리되어 실제 대상이 움직이는가 |
| mask/glyph source | 사물의 윤곽, 글자 안의 빛/표면 | 이미지 특징이 최종 형태에서 보이는가 |
| parallax layer | 전경/중경/배경을 다른 속도로 전개 | 층이 납작한 같은 팬·줌과 구별되는가 |
| collage/재질 | 조각의 조립·해체, 표면의 주름/반사 | 이미지 조각이 사건의 주체인가, 장식 삽입인가 |

이 표는 API enum이 아니다. 필요한 역할을 새 이름으로 기록할 수 있으며, 그 역할을 실행하는 코드는 장면에 직접 작성한다. `roles` 문자열을 적거나 REEL.img로 로드한 사실만으로 역할이 구현됐다고 하지 않는다.

한 장을 전면 배경으로 길게 유지할 때는 그 공간을 유지하는 이유와 내부 사건을 설명한다. 작은 사진은 장소/시점/질감/목표 중 실제 역할을 맡긴다. 지워도 의미·공간·질감이 변하지 않는다면 제거하거나 역할을 다시 설계한다. 이미지 수를 늘리는 것을 다양성 개선으로 대체하지 않는다.

## 생성과 검수

- 콘셉트의 매체·재질·색/광원·구도와 필요한 실루엣/alpha·여백을 프롬프트로 옮긴다. genre라는 단어만으로 사람·복장·국적·나이·성별을 정하지 않는다. 인물이 필요 없으면 가수를 만들지 않는다. 실존 인물 생성·브랜드 모방을 새 콘셉트에 끼워 넣지 않는다.
- 움직일 오브젝트는 경계/돌출부가 모두 들어오게 만든다. 투명 자산은 `transparent_background:true`로 생성하고 실제 alpha를 확인한다. 체커보드를 투명으로 오인하지 않는다. 불투명 plate와 독립 오브젝트를 같은 생성 사진 안에 구워 합성을 막지 않는다.
- 장면별로 필요한 비율을 쓴다. 모든 이미지를16:9 또는 CD원형 크롭으로 강제하지 않는다. 실제 합성 크기에서 세부·자막 대비·크롭을 확인한다.
- 생성 결과를 먼저 직접 열어 내용·사물 구조·문자/로고·조명·연속성을 확인한다. 수정은 image_gen 편집을 사용한다. 원본/선택본/수정 프롬프트·도구·실제 경로·SHA를 남기고 프로젝트로 복사한다.
- 승인 가사·곡명·선택 채널명은 가능하면 검증 가능한 native 텍스트로 합성한다. 썸네일에 글자를 직접 생성했다면 실제 한글과 크롭을 확인하고 고친다.

## 실행 연결

[media 계약](composition-contract.md)의 id/path/roles/source를 작성해 `native_project.py apply --media ...`로 실제 파일을 검증·고정한다. helper는 이미지 생성 도구를 직접 호출하지 않으며 source 기록은 제출된 근거이지 독립 생성 인증이 아니다. generated/reuse/provided를 구분한다.

`FILM_IMAGES[id]`와 `FILM_MEDIA_READY`로 디코드된 자산을 장면에서 쓴다. 픽셀/자연 크기가 필요한 async setup은 `await FILM_MEDIA_READY` 후 마스크·입자·표면을 준비한다. render는 원곡 시각에 따라 drawImage/clip/texture/transform을 직접 호출한다. 외부 캐시나 CDN에 의존하지 않는다.

style frame과 전·중·후 동작 띠를 보고, 필요하면 같은 시각의 asset on/off 비교로 **이미지가 실제로 화면의 의도한 부분을 만드는지** 확인한다. 픽셀 차이는 사용 증거이며 의미 적합성의 자동 합격점이 아니다. 생성 근거, 로드/디코드, 실제 사용, 미술 판정을 각각 기록한다.

## 썸네일과 음악 시작

썸네일은 별도 납품 자산이다. 이미 요청한 첫0.5초 카드는 `opening.thumbnailId/seconds`로 보존한다. 새 오프닝은 곡의 시작과 요청에 맞춰 직접 모션 또는 고정 카드를 선택한다. 카드가 있어도 음악/가사/전체길이는 이동하지 않고, 원곡 중간 proof에는 다시 붙이지 않는다. 카드 최상단 gate와 최종 sub4 종료 프레임은 별도로 확인한다.

생성 오브젝트의 현·손·피크·접합부 같은 후속 모션은 실제 이미지를 열어 anchor와 방향을 정한 뒤, 자연 크기→합성 fit/회전/스케일의 같은 좌표 변환으로 연결한다. 자산이 제대로 로드돼도 이 관계가 어긋나면 다른 물체처럼 보인다.

첫 0.5초 고정 카드도 출력 크기 canvas에 한 번 래스터화해 실제 자산의 중앙 cover 크롭을 고정한다. 같은 썸네일을 다시 표시할 때 브라우저 IMG의 재샘플링/합성 상태에 따라 픽셀이 바뀌지 않는지 원점 역순 검사로 확인한다.
