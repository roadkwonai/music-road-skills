소유권·SQLite 상세 안내

이 페이지의 기능과 다음 단계를 확인한 뒤 제작실에서 작업하세요.

저장공간 관리의 소유권 추적은 파일을 어디서 왔는지, 어떤 음악·프로젝트와 연결되는지, 지금 정리해도 되는지를 빠르게 판단하기 위한 작은 관리 원장입니다. 이 페이지는 상태 카드와 제거 확인 모달에 나오는 용어를 설명합니다.

두 SQLite 파일의 역할

프로필 데이터 폴더의 storage.sqlite3는 프로젝트·음악 그룹·경로 소유권, 크기·수정 시각, 최소 이벤트와 스캔 통계를 관리합니다. 작업 폴더의 .roadmusic/history.sqlite3는 게시를 통과한 납품 버전·파일 해시·변경 사유·diff 원장입니다.

실제 음원·영상·원가사·SRT·이미지·엔진 JSON은 원래 파일 위치에 둡니다. 프레임 이미지, 미디어 BLOB, 렌더 로그 덤프를 SQLite에 넣지 않으므로 같은 자료를 이중 보관하지 않습니다.

텍스트 예시
storage.sqlite3: 소유권·경로·최소 변경/정리 이력·스캔 통계
.roadmusic/history.sqlite3: 검증된 납품 버전·diff
실제 파일: 원음·완성본·가사·영상·엔진 JSON·승인 자산

상태 카드와 소유권 추적

상태 카드는 항목마다 이름, 활성 여부, 필요한 조건, 현재 확인한 조건, 비활성 이유를 보여 줍니다. 활성 상태는 해당 검사를 실행할 수 있다는 뜻일 뿐 삭제할 파일이 있다는 뜻은 아닙니다. Git 저장소가 없는 설치는 Git 공간 관리가 비활성화되며, 이 경우 Git 분석을 시도하지 않습니다.

기본 소유권 추적은 저장된 SQLite 색인을 사용합니다. 실제 작업 폴더 변화가 의심될 때만 새로 고침을 실행하세요. 새로 고침은 경로·크기·수정 시각을 일괄 색인하지만 파일 삭제, 미디어 해시 재계산, Git 객체 분석, SQLite VACUUM을 실행하지 않습니다.

명령
node cli/road-music.js storage:status
node cli/road-music.js storage:tracking
node cli/road-music.js storage:tracking --json '{"refreshWorkspace":true}'

미연결처럼 보이는 항목

.roadmusic, .harness, .omx, _workspace와 같은 폴더는 Road Music 제작물 자체가 아니라 관리·검수·실행에 필요한 영역일 수 있습니다. 화면에서는 이를 보호된 관리 영역으로 표시합니다. 이 폴더가 음악 그룹에 연결되지 않았다는 이유만으로 미연결 제작물이나 캐시가 되지는 않습니다.

음악·프로젝트·관리 영역 어디에도 소유 근거가 없는 폴더는 소유권 미확인·보호로 표시합니다. 목록에서 누락시키지 않아 용량을 확인할 수 있지만, 자동 일괄 정리와 일반 캐시 정리에는 포함하지 않습니다. 원인을 확인한 뒤 구조 전환이나 명시 선택한 제거 계획에서만 검토합니다.

정리와 제거의 차이

정리는 재생성 가능한 등록 cache와 검증된 작은 잔재를 다룹니다. storage:reconcile-preview에서 목록과 보호 사유를 확인하고, 받은 계획만 storage:reconcile-cleanup --confirm으로 실행합니다. 현재 기본 후보는 .DS_Store입니다.

프로젝트/그룹 제거는 완성 파일을 포함할 수 있는 별도 작업입니다. 프로젝트 또는 음악 그룹을 선택하면 파일 범위·공유 원음·활성 작업·핀 보호·SQLite live 행 제거 영향을 먼저 확인합니다. 같은 음악 그룹의 모든 완성본을 지울 수 있으므로 모달의 포함 목록과 경고를 읽은 뒤에만 확인하세요.

제거가 적용 중 중단되면 같은 계획의 복구를 선택할 수 있습니다. 복구는 격리된 파일, 원래 경로, SQLite 상태가 모두 일치할 때만 원래 상태로 되돌립니다. 불일치나 파일 변조가 있으면 안전을 위해 격리 자료를 유지하고 원인을 표시합니다.

명령
node cli/road-music.js storage:reconcile-preview
node cli/road-music.js storage:reconcile-cleanup --json '{"planId":"응답의 계획 ID"}' --confirm
node cli/road-music.js storage:project-remove-preview --json '{"projectId":"응답의 프로젝트 ID"}'
node cli/road-music.js storage:group-remove-preview --json '{"groupId":"응답의 음악 그룹 ID"}'
node cli/road-music.js storage:entity-recover --json '{"planId":"중단된 제거 계획 ID"}' --confirm

이력과 성능

제목·가사·음원·모션그래픽 변경, 게시, 정리는 최소 이벤트로 기록합니다. 화면의 버전·변경 내역은 이 이벤트와 납품 원장을 함께 사용합니다. DB 조회는 일반적으로 파일 트리를 다시 읽지 않습니다. 큰 작업 폴더 스캔은 명시적으로 요청할 때만 수행하며, 삭제 직전에는 대상 파일·보호 상태·변경 여부를 다시 확인합니다.

자동 VACUUM, 매 화면 진입의 Git 전체 검사, 프레임/로그의 DB 저장은 하지 않습니다. 이 방식으로 일반 설치와 개발 환경 모두에서 필요한 항목만 추적하면서 불필요한 저장공간 검사 시간을 줄입니다.

문제가 생기면

  • 비활성필요한 설치·경로·상태가 없다는 뜻입니다. 파일을 억지로 검사하거나 삭제하지 말고 표시된 이유를 확인하세요.
  • 소유권 미확인아직 삭제 대상이 아닙니다. 경로와 용량을 확인하고 필요한 경우 구조 전환 점검을 사용하세요.
  • 제거가 차단됨공유 원음, 활성 작업, 핀, 외부 경로 또는 변경된 파일이 보호 중일 수 있습니다. 새 미리보기로 다시 확인하세요.
  • 변경 내역이 비어 있음기존 결과에 수정 사유가 기록되지 않았을 수 있습니다. 시스템은 과거 이유를 추측하지 않습니다.
