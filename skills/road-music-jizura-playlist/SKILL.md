# JIZURA 음악 모션그래픽

음원을 곡 전체 길이의 **JIZURA 네이티브 모션그래픽**으로 만든다. 작업 AI가 음악의 의미와 감정 변화를 해석하고, 로컬 JIZURA가 실제 스타일·타이포·기하학·카메라·전환을 그린다. 음악 분석→연출→편집 가능한 `.jizura.json`→실제 MP4까지 이어간다. 기존 곡과 가사는 보존한다.

시작 시에는 현재 읽은 이 `SKILL.md`의 실제 절대 부모 경로를 `JIZURA_SKILL`에 넣어 [사용 시 업데이트 확인](../road-music-skills-update/references/use-time-check.md)을 한 번만 적용한다.

개인 스킬이며 Road Music 앱 기능이나 공식 JIZURA CLI로 소개하지 않는다. 음악 생성·LTX 설치·CD 영상·다른 스킬의 카탈로그 갱신은 별도 요청이다. 단순 사용 가능 여부 질문에는 설명으로 답하고, 제작 요청이면 도구로 제작을 완주한다.

공식 배포 스킬을 설치한 것이 아니라, **공식 JIZURA 엔진과 한국어 편집기를 활용하는 개인 Agent 스킬**이다. 공식 기능과 출처는 [기능 분석](references/official-features.md)에 있다.

## 호스트별 이미지 도구

ChatGPT/Codex에서는 내장 `image_gen`, 로컬 Claude Code CLI/IDE에서는 실제로 읽은 `gpt-image` 스킬의 ChatGPT 로그인 Codex CLI 브리지를, Antigravity에서는 현재 세션의 네이티브 이미지 생성 기능 또는 내장 `image-generator` 경로를 사용한다. [공통 이미지 계약](../road-music-video-studio/references/image-providers.md)을 따른다. `image_gen` 전용 인자는 ChatGPT 경로이며 Claude의 브리지 인자와 Antigravity 도구명·모델 옵션을 추정하지 않는다. Claude에서 `gpt-image`가 없으면 의존성 누락을 보고하고 로그인·설치·유료 API 대체를 하지 않는다. 실제 파일·도구·반환 모델을 기록하고 동일한 자산 검수/렌더 계약으로 전달한다. **이미지가 없는 JIZURA 절차형 연출은 이 의존성이 필요 없으며 그대로 제작한다.**

## HTML 제작·검수 화면
HTML을 사용하는 단계에서는 [단계별 페이지 열기](../road-music-video-studio/references/page-flow.md)에 따라 필요한 화면을 Ego 브라우저에서 실제로 열어 확인한다. 이미 저장한 선택을 다시 묻거나 같은 화면을 불필요하게 다시 로드하지 않는다.


실제 영상 제작은 [공통 HTML 영상 제작실](../road-music-video-studio/SKILL.md)을 함께 사용한다. 스타일과 음악을 보고·들으며 고르고, 기획/이미지·부분 영상·최종 결과·수정 의견을 같은 프로젝트 화면에 게시한다. 이미 받은 선택은 유지하고 저장된 selection.json/feedback.json을 실제로 읽어 이 스킬의 입력에 반영한다. 표시용 페이지 생성이나 버튼 저장을 렌더 완료로 보고하지 않는다. 생성 HTML은 저장소 `DESIGN.md` 토큰과 번들 Paperlogy를 적용하며, 외부 공식 JIZURA 편집기의 Canvas·렌더 결과는 수정하지 않는다. HTML은 제작·검수 인터페이스이며, 엔진별 실제 생성·편집·렌더와 원곡/가사 시계는 아래 절차가 맡는다.

## 먼저 읽을 자료

- 첫 사용: [제작·명령·입력 형식](references/production.md). 확인된 JIZURA 0.10.1을 재사용한다.
- 추천 선택/커스텀 요청: 아래 HTML 선택 흐름과 [제작 절차의 Studio](references/production.md#html-studio)를 읽고 실제 페이지를 연다. UI 자체를 확장할 때는 [기획·설계](references/studio-design.md)를 읽는다.
- 공식 기능을 세밀하게 조정할 때: [28개 기능·필드·제약](references/official-features.md). `themeId` 선택과 재구성 실행, 행/컷 잠금, 타이밍 시계, 출력 범위를 구분한다.
- 확인한 동작과 검수 한계: [보완 검수 기록](references/verification.md). 이 날짜의 검증을 모든 곡·부품 조합의 품질 보증으로 확대하지 않는다.
- 곡의 방향 선택: [음악 해석과 비트 연출](references/direction.md), `assets/directions.json`의 실제 엔진 스타일 10개 출발점. 혼합/목록 밖 장르도 원곡 근거로 설계한다.
- 화려함·스타일 조합: [단일·리듬 변주·멀티스타일 제작](references/style-composition.md). 추천안의 구성 방식과 강도를 따로 고르고, 여러 전역 스타일은 구간별 native 출력 뒤 `compose`로 합친다.
- 가사가 있는 제작·수정: [가독성 자동 검수·수정과 싱크 근거 관리](references/lyrics-readability.md)를 적용한다. native 후보 검사와 실제 최종 MP4 프레임 검수를 구분하고, 확정·자동 정렬·추정 상태를 원음/원문/시각에 묶어 보존한다.
- 사용자 튜토리얼과 추가 작품: [사례 조사](references/research.md). 제작 확인·조회 지표·관측한 움직임·편집적 해석을 구분한다. 확인되지 않은 사례를 인기 JIZURA 작품으로 승격하지 않는다.

## 여러 연출안 추천과 선택

음악마다 기본 **3개의 구별되는 연출안**을 추천한다. 단일 스타일, 같은 스타일 안의 구간별 리듬 변주, 여러 전역 스타일의 조합을 곡의 장르·가사·강약·취향에 맞게 비교한다. 비트가 강한 곡을 늘 단일 스타일로 제한하거나, BPM만으로 화려한 조합을 강제하지 않는다. 단일 스타일을 원하면 그 범위 안에서 추천한다. 같은 설정의 seed만 바꾼 것은 별도 연출안으로 세지 않는다.

단일 스타일 후보는 기존 `direction.recommendations`의 `profile/reason`과 HTML 추천 카드를 사용한다. 조합안은 `direction.compositionRecommendations`에 `id/name/mode/intensity/reason/parts`를 기록하고 채팅 비교표·실제 합성 미리보기로 제시한다. 이 배열을 현재 HTML이 자동 표시하지는 않는다. 채택한 안은 `direction.composition`에 보존해 이후 제작·재개에 사용한다. 구성 방식·구간 역할·기법·강약이 실제로 달라야 하며, 같은 주 스타일로 시작하는 단일안과 조합안도 가능하다. `direction.profile`은 출발점이지 전곡을 한 스타일로 제한하는 규칙이 아니다.

단일 프로젝트용 HTML은 **추천·빠른 설정 / JIZURA 전체 편집기 / 기능 안내**로 구성한다. 추천 클릭은 같은 원음의 실제 엔진 프리뷰를 바꾸며, 선택 뒤에도 스타일·강도·배색·서체·행/컷·타이밍·출력값을 커스텀할 수 있다. 전체 편집기는 로컬 공식 한국어 HTML을 그대로 재사용한다. 초기 프로젝트가 있으면 그대로 열고 추천으로 몰래 덮어쓰지 않는다.

작업 AI의 곡 해석이 있으면 그것을 우선한다. 웹 페이지 단독 업로드의 BPM/에너지/키워드 후보는 **보조 추천**으로 표시하며, 가사 의미나 장르의 AI 분석 완료라고 하지 않는다. 다른 음원으로 바꾸면 이전 곡 해석/시각의 재검수 상태를 유지한다. 저장은 검수 완료 선언이 아니다.

선택형 제작에는 실제 미리보기와 여러 후보를 보여 주고 선택된 구성을 제작한다. 기존 Studio는 한 native 프로젝트를 편집하므로, 여러 전역 스타일의 조합은 구간 프로젝트 묶음·합성 manifest·결과 미리보기로 제공한다. Studio의 스타일 드롭다운이나 `themeId`만 바꿔 시간순 혼합이 된 것처럼 안내하지 않는다. 자동 제작을 위임했다면 근거 있는 상위안으로 진행하고 별도의 승인 절차를 새로 만들지 않는다.

## 제작 흐름

1. **음원과 시계** — 파일, 실제 길이, 순서, 제공 가사/LRC/SRT/정렬 결과를 확인한다. 여러 곡은 원음·가사·시계를 독립적으로 보존한다. 파일 미지정이면 맥락의 확정 음원을 찾고, 여러 후보로 결정할 수 없을 때만 묻는다. 이 스킬은 새 음악을 생성하지 않는다.
2. **먼저 측정** — `assets/probe.jizura.json`으로 `render-jizura.mjs --inspect`를 실행해 원음 해시·BPM/비트·에너지·실제 스타일/부품을 얻는다. 기존 제작 기록을 찾았다면 곡명만으로 연결하지 말고 원음 해시로 같은 곡인지 확인해 원가사를 우선한다. 박자 오차가 보이면 리듬 검증기로 실제 어택과 비교한다. 수치는 장르 판독이나 가창 정렬 결과가 아니다. 청취할 수 있으면 도입·벌스·후렴·브레이크·끝을 확인하고, 듣지 못했다면 청취 완료로 쓰지 않는다.
3. **곡별 연출과 후보** — `direction.json`에 장르 근거, 가사의 주제/감정 변화, 구간의 음악적 이유, 세 추천의 차이, 모티프·리듬 문법을 기록한다. 구성 방식과 화려함은 별도 축이다. 강한 곡은 주 스타일에 다른 스타일·키네틱·카메라·전환을 조합하는 안도 적극 제안하고, 잔잔한 곡도 가사의 전환점에는 대비를 줄 수 있다. 명시된 취향·원문·가창 시각이 우선이다. 후렴/드롭의 확장과 브리지의 감산을 sections[].jizura·cue·directing으로 옮긴다. 여러 전역 스타일은 구간 프로젝트로 구현하며 서술이나 색 변경만으로 혼합 완료라 하지 않는다.
4. **가사 또는 무자막** — 제공 시각을 원음 초 단위 `cues.json`으로 옮긴다. 시작뿐 아니라 끝·무가사 구간도 반영한다. 실제 단어 시각 없이 문장을 잘라 단어 싱크로 부르지 않는다. 가사만 있으면 기존 로컬 정렬 도구로 초안을 만들고 검수 상태를 보존한다. 도구/가사가 없으면 무자막 그래픽 제작을 계속하되 가사 싱크를 완료했다고 하지 않는다. 무자막은 `instrumental:true`; 이 값은 그래픽 모드이며 실제 무보컬 여부는 별도 기록한다. 가짜 가사·가수·임의 슬로건을 만들지 않는다.
5. **실제 프로젝트** — `project.py build`로 새 출력 폴더를 만든다. 곡명/아티스트는 메타데이터에 보존하고 화면에는 요청한 cue만 넣는다. 채널명·곡 목록·숫자 HUD는 자동 삽입하지 않는다. 부품 id는 실행의 `registry.json`에서 고른다. `--inspect`로 생성한 **실제** `plan.json`의 컷·가사·시각·전환을 확인한다. 반복 구절은 cue.motif로 연결하고, 효과 시각과 색면은 native lockedCuts로 저장한 directed.jizura.json을 다시 열어 재현을 확인한다. 설정 작성만으로 적용 완료라 하지 않는다.
6. **미리보기와 본편** — 곡의 특징이 드러나는 12~20초 정도로 크기·글꼴·대비·발성·타이밍을 확인한다. 조합안은 대비 구간과 스타일 연결부도 비교하며, 화려한 안을 만들기 전에 모든 효과를 일괄 제거하지 않는다. 문제를 수정하고 전곡을 렌더한다. 같은 곡의 스타일 구간은 `compose`, 여러 곡은 기존 `assemble`을 사용한다. 지정 길이와 미리보기만 요청한 범위를 지키며 일반 제작 위임에 새 승인 절차를 만들지 않는다.
   가사가 있으면 native 렌더가 만든 `readability-final`을 검수하고, assemble/compose가 **합성된 최종 MP4**에서 자동 생성한 검수 자료도 확인한다. 모든 표시 행의 시작·중간·끝과 위험 효과 시점의 프레임을 열어 확인하고, 문제 행만 수정·새 출력·재검수한다. `decision-template.json`을 실제 프레임 검수 후 작성하고 검수 판정 명령으로 현재 영상·프레임 SHA를 대조한다. 후보 없음이나 재생 성공을 가독성·청취 통과로 승격하지 않는다.
7. **납품** — 최종 MP4, native 프로젝트, 원문 cue/출처·정렬 상태, direction·analysis·실제 plan·검증 JSON을 제공한다. 멀티스타일은 구간별 프로젝트와 `compose` manifest도 함께 보관한다. 원음과 최종 길이, 부분 미리보기의 원음 범위를 구분한다. 외부 게시/음원 전송은 별도 요청이다.

## 품질 판단

- **곡 표현**: 색만 바뀐 동일 템플릿 대신 감정 변화·단어 의미·악기 역할을 배치와 움직임으로 표현한다. 제목/장르 표시를 늘려 해석을 대신하지 않는다.
- **그루브**: 두 가지 이상의 음악적 사건(예: 스네어·베이스·필인·보컬 진입)에 서로 다른 움직임을 대응시킨다. 후렴 모티프를 회수하고 클라이맥스에서 확대한다. 저에너지 곡은 작은 진폭·긴 호흡으로 리듬을 표현한다.
- **가사 전달**: 원문/순서/타이밍 상태를 보존하고 한국어 단어를 잘못 분절하거나 효과로 오래 가리지 않는다. `typeset:true`는 0.2초 선행을 적용하므로 기본은 false다. 의도한 선행은 원래 가창 앵커와 따로 기록한다.
- **실제 검수**: 규격/길이/오디오 트랙, 원음 포함 재생, 인트로·첫 가사·후렴·브레이크·곡 전환·끝 프레임을 확인한다. BPM·파일 존재만으로 청취 품질·정확한 가창 싱크·인기도를 확정하지 않는다.

출력은 새 경로로 만들고 기존 프로젝트/브라우저/다른 렌더를 건드리지 않는다. 실패 시 입력·로그·부분 결과를 보존하고 원인을 확인한 뒤 관련 구간만 다시 만든다. 같은 실패가 반복되면 실제 원인과 복구 경로를 보고하며 무한 재시도하지 않는다.

HTML 제작·선택·검수 화면에는 [공통 DESIGN.md](../road-music-video-studio/assets/design/DESIGN.md)와 번들 Paperlogy를 적용한다. 현재 프로젝트의 DESIGN.md가 있으면 이를 먼저 대조한다. 화면 열기는 [단계별 페이지 이동](../road-music-video-studio/references/page-flow.md)의 같은 Ego 페이지를 재사용하며, 이미 열린 화면에 새 탭을 추가하지 않는다.
