# 음악 해석 → 화면의 움직임

## 곡 브리프

`direction.json`은 엔진 설정과 해석 근거를 함께 보존한다. 혼합 장르를 강제로 하나로 줄이지 않는다.

단일 스타일·구간별 리듬 변주·여러 전역 스타일의 조합을 모두 연출 후보로 연다. 스타일 수와 화려함은 별도 판단이며, 강한 음악을 항상 한 스타일과 소수 효과로 제한하지 않는다. 추천·구성·실행 계약은 [스타일 조합](style-composition.md)에 있다.

- `genre`: 사용자/제작 메타데이터/청취에 의한 장르와 불확실성. 음량·BPM만으로 분류하지 않는다.
- `interpretation`: 가사의 화자·대상·갈등·변화, 중심 이미지와 반복 구절. 연주곡은 악기·질감·공간·감정 곡선을 사용한다.
- `sections`: 원음 초 기준 시작/끝, 역할, 근거, 에너지와 감정. RMS 변화는 후보 경계이며 절 구조의 정답이 아니다.
- `motifs`: 실제 단어/악기/음악적 사건 → 시각 요소 → 움직임 → 회수 구간. 실제 가사에 없는 문구를 추가할 권한은 아니다.
- `profile`, `references`, `rationale`, `timingStatus`, `listeningReviewed`: 선택과 검수의 근거.

예: 이별 가사에 밝은 댄스 비트가 있는 곡은 선명한 박자와 차가운 여백을 함께 설계할 수 있다. 장르명만으로 모든 가사의 감정을 밝게 만들지 않는다.

## 실제 스타일 출발점

`"$JIZURA_PY" "$JIZURA_SKILL/scripts/project.py" styles`가 현재 10개 출발점을 보여준다. JIZURA 소스에서 존재를 확인한 스타일의 **연출 제안**이다. 원작 설정을 입수했거나 인기순으로 검증한 프리셋이라는 뜻이 아니다.

| 출발점 | 엔진 id | 주된 어휘 | 곡에 맞게 바꿀 것 |
| --- | --- | --- | --- |
| 네온 시티 | synth80 | 검정·마젠타·시안, 네온과 스캔 | 베이스 이동, 스네어 정렬, 후렴의 공간 확장 |
| 애시드 펄스 | acid | 산성 녹색·마젠타, 거친 활자 | 드롭 직전 정지, 스케일 변화, 브레이크의 감산 |
| 레드 임팩트 | crimson | 붉은 색면과 큰 활자 | 실제 랩 구절, 스네어 컷, 핵심어 고정점 |
| 캔디 팝 | candy | 파스텔과 둥근 활자 | 시각이 확인된 바운스, 후렴 반복 포즈 |
| 에디토리얼 컷 | newsprint | 신문·잉크·망점, 비대칭 | 내용 대비를 패널로, 필인의 레이아웃 전환 |
| 누아르 그루브 | noir | 먹색·백색·앰버·청록 | 스윙의 지연, 고스트 노트, 낮은 진폭 |
| 페이퍼 발라드 | paper | 종이·남색·자홍, 세리프 | 구절 읽는 시간, 후렴 확대, 아웃트로 정리 |
| 딥 오션 | ocean | 짙은 파랑·잔광·물방울 | 프레이즈와 잔향, 무드럼 구간의 호흡 |
| 크래프트 노트 | kraft | 종이 조각과 스탬프 | 작은 당김음, 보사/어쿠스틱의 반복 |
| 골드 나이트 | gold | 검정·금빛·아이보리 | 선율 상승과 클라이맥스, 절제된 장식 |

다른 스타일도 `registry.json`에서 확인해 `direction.jizura.style`로 쓸 수 있다. 명시한 색/서체는 `jizura.colors/fonts`의 지원 형태로 적용한다. 한국어는 `lang:"ko"` 또는 auto로 실제 글리프를 확인한다. 장르만으로 문화적 소품이나 인물을 강제하지 않는다.

## 리듬 문법

주 모티프 하나와 보조 모티프 한두 개에서 출발해 역할을 나눈다. 복잡한 곡은 필요한 만큼 확장한다.

| 음악적 사건 | 움직임 후보 | 확인 근거 |
| --- | --- | --- |
| 킥/베이스 어택 | 작은 압축·도형 팽창·정렬점 이동 | 실제 저역 어택과 beat 후보 비교 |
| 스네어/클랩 | 하드컷·패널 교환·굵기/위치 전환 | 백비트 위치 |
| 하이햇/셰이커 | 선/점/보조 요소의 박자, 메인 문장은 유지 | 분할 박과 스윙 |
| 필인/브레이크 | 한 번 분해·밀어내기·방향 전환 뒤 안정된 홀드 | 프레이즈 끝과 다음 진입 |
| 보컬 구절 시작 | 읽는 덩어리의 등장/마스크/이동 | 정렬 결과와 실제 가창 onset |
| 후렴/드롭 | 큰 활자·넓은 배치·굵기·밀도 | 곡 구조와 감정 변화 |
| 브리지/무음 | 요소 감산·여백·느린 카메라, 재진입 준비 | 에너지·편성 변화 |

`registry.json`의 layout/enter/hold/exit/decor/treat/bg/cam/trans를 골라 cue별 `jizura`로 옮긴다. 컷을 늘리면 `cuts`와 **행 시작 기준 초**인 `cutTime`을 함께 제공한다. 단어 시각이 없으면 `cuts:1`로 전문을 유지하고 장식/카메라에서 박을 만든다. `cutTech`는 해당 컷의 선택을 덮어쓴다. 의미의 반전·후렴 재등장 등 실제 사건에서 배치를 바꾼다.

자동 BPM은 70–180 범위의 고정 템포 휴리스틱이다. 반/배속, 무박자·템포 변화·스윙·드럼 없는 곡을 확인한다. 수동 `bpm`은 검출 비트를 `beatOffset`부터 균등 그리드로 바꾼다. 검출 시작점이 다운비트라는 보장도 없다. 가사 시각을 비트에 맞춰 밀지 않고 시각 요소를 검증한 리듬에 맞춘다.

매 박마다 글리치/번쩍임을 올려 역동성을 대신하지 않는다. 준비→어택→홀드→릴리스, 큰 것/작은 것, 정지/이동의 차이를 만든다. 기본 flash는 끄고 강조는 패널·확대·색 대비로 만든다. 저에너지 곡은 작은 움직임에도 실제 리듬 반응을 유지한다.

이는 화려한 효과나 여러 스타일을 피하라는 뜻이 아니다. 드롭·랩·감정 반전에 어울리면 강한 기법과 대비 스타일을 추천하고 구간에 실제 적용한다. 공통 서체·모티프를 유지하며 다른 구간을 대비시킬 수 있다. 플래시·글리치·컷 빈도·배색 전환은 각각 조절한다.

## 실제 플랜 확인

엔진은 미지원 id를 조용히 대체할 수 있다. 래퍼 registry 검증 후 실제 `plan.json`의 시작/끝·레이아웃·전환을 확인한다. `cuts:1`을 지정한 행은 native unify/kime가 비활성일 수 있다. 전문 보존을 위해 cuts를 삭제해 자동 분절시키지 않는다. 반복 후렴은 cue.motif와 공개 lockedCuts로 모습·동작을 회수하고 실제 계획을 비교한다. sections[].jizura의 동작과 directing 스코어가 실제 cut/event로 연결되어야 한다.

긴 행은 엔진이 `visEnd`를 제한한다. 가창보다 먼저 사라지면 실제 구절 경계로 나누거나 원문을 보존하는 별도 자막 레이어를 합성한다. cue end를 늘리는 것만으로 해결됐다고 하지 않는다. 첫 벌스·후렴·빠른 구절·끝에서 읽는 시간과 발성 앵커를 확인한다.


## 실제 곡 미리보기에서 드러난 선택 기준

자동 레이아웃 중 경고판/표지판/가격표처럼 가사 밖 문구를 붙이는 것은 곡의 의미와 요청에 맞을 때만 사용한다. hideNo/hideTime만으로 모든 장식의 외국어·라벨이 사라진다고 가정하지 않는다. 실제 프레임에서 확인하고 해당 layout/decor를 교체한다.

원호·원형·큰 세로 글자처럼 독특한 배치는 읽기 부담이 생길 수 있다. 구절 전체가 지속해서 기울어 있으면 수평 주 가사를 확보하거나 해당 구절을 center/frameBox 같은 읽는 배치로 바꾼다. 장식용 복제 글자의 잘림과 읽어야 할 주 가사의 잘림을 구분한다. 임팩트는 큰 가사의 공간 점유율·대비·정지 후 확장으로도 만들 수 있다.

한글의 전체 문장은 native center가 폭에 맞춰도 hold의 가로 확장과 카메라 줌이 겹치면 가장자리에서 잘릴 수 있다. 완성 프레임에서 어절 끝이 잘리면 해당 구절의 확대 중첩을 줄이거나 더 넓은 여백을 두는 frameBox 배치로 바꾼다. 밝은 glow가 획을 뭉개면 softShadow/명확한 대비로 바꾸고 다시 읽는다. 곡의 모든 배치를 일률적으로 작게 만드는 대신 문제가 드러난 구절을 수정한다.
