## 구현 담당자용 임베딩 근거와 주의

가장 얇은 재사용 경로는 pinned 한글 `ko/index.html`을 추천 HTML과 같은 localhost host/port로 서빙하는 것이다. 이 HTML은 native UI, 실시간 Canvas,오디오분석, 프로젝트파일입출력,상세편집, MP4/PNG/AE내보내기를 이미 포함한다. 외부 jizura.net iframe을 직접 조작하는 방식에는 cross-origin 접근제한이 있고, upstream에 postMessage 프로토콜은 없다. 파일을 더블클릭하는 file:// origin도 브라우저별 opaque origin이므로 동일폴더라고 접근가능성을보장하지않는다. [MDN same-origin](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy).
공식 J.uiApi에 loadProject/mergeProject는 없다. JSON import는 fileProject change event 경로에서 mergeProject/sanitization/migration/history reset/restoreFonts 등을 수행한다. 신뢰되지않는 JSON을 J.ui.project에 그대로대입하지말고 native프로젝트입력흐름을재사용하거나 필요한경계검증을해라. 프로젝트대입뒤 syncUI→replan→flushSave로preview/state를맞출수있으나이는trusted/generatedpatch에한정한다.
추천 적용 전 기존 프로젝트 snapshot 보존. themeId선택은 randomize전까지 아무효과없다. 실제 추천은 음악/가사 해석에따른 project fields + verifiedregistry기법 + cue/line/cut설정이어야한다. 선택된 제작안은 단일 스타일 또는 스타일 조합일 수 있다. 현재 Studio의 profile 선택은 전역 스타일 하나를 바꾸며, 멀티스타일은 구간 프로젝트·합성 manifest를 사용한다. 860개커스텀컨트롤을다시구현할필요없다.
J.uiApi 훅은 CEP host용 명시노출이나 stable publicSDK는 아니다. pinnedSHA유지+부팅시필수훅/스타일/그룹존재확인이적합하다. sameoriginiframe contentWindow.J 사용시부팅완료후조회. sandbox로origin을opaque하게만들면호스트접근이끊긴다.
프로젝트저장은서버파일에자동write하지않고브라우저download이다. 로컬서버는127.0.0.1에바인딩하고제공범위를출력폴더/고정runtime로제한. 여러project탭은같은origin localStorage/IndexedDB를공유하므로자기profile/origin을분리하고기존열린JIZURA작업을초기화하지않는다.
음원은사용자File객체로 loadAudioFile할수있다. crossoriginremoteaudio를가져와사용자업로드처럼보이게하지말것. 브라우저보안/자동재생은사용자제스처또는nativeplay를필요로할수있다.
대형MP4 직접저장은 showSaveFilePicker를click즉시호출해야하며await전이어야한다(native runExport이미구현). iframe에서지원안되면native편집기를같은origin새탭으로열고일반download를사용. [MDN file picker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker).
