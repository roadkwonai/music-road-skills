# 단일 스타일과 여러 스타일의 조합

스타일 수 자체가 좋은 영상이나 나쁜 영상을 결정하지 않는다. 곡의 전개·가사·비트에 맞는 변화와 반복의 관계를 설계한다. 통일감은 한 배색·한 배치만 반복하라는 뜻이 아니다. 공통 서체·원문·모티프를 유지하면서 후렴을 더 크게, 브리지를 더 조용하게 만들 수 있다.

## 추천 방식

<a id="recommend"></a>

| 구성 방식 | 추천할 상황 | 실제 제작 |
| --- | --- | --- |
| `single` 단일 스타일 | 특정 스타일 요청, 일관된 채널 이미지, 가사 중심 | native 프로젝트 1개. 같은 스타일 안에서도 다양한 부품과 강약 사용 가능 |
| `adaptive` 구간별 리듬 변주 | 같은 시각 정체성으로 벌스·후렴의 대비를 살릴 때 | 전역 스타일 1개 + 구간별 layout/enter/hold/exit/decor/treat/bg/cam/trans·효과·내부 배색 |
| `multi-style` 여러 스타일 조합 | 뚜렷한 드롭/후렴·장르 전환·가사의 감정 반전, 강한 대비를 원하는 곡 | 전역 스타일이 다른 native 프로젝트들을 구간별 렌더하고 `project.py compose`로 합성 |

위 mode는 **이 스킬의 연출 메타데이터**이며 공식 JIZURA 옵션이 아니다. 구성 방식과 강도(`restrained/balanced/bold`)도 별도다. 단일 스타일을 화려하게, 멀티스타일을 절제해서 만들 수도 있다.

추천은 장르·악기·저역 어택·리듬 분할·에너지 변화·가사 의미·요청 취향을 함께 고려한다. BPM 하나로 모드를 자동 확정하지 않는다. 의미 해석이 없으면 리듬 보조 추천이라고 표시한다. 사용자가 단일 스타일을 원하면 조합을 강제하지 않는다. 강렬한 표현이 어울리면 조합안을 상위에 추천할 수 있다.

`direction.compositionRecommendations`에 `id/name/mode/intensity/reason/parts`를 기록하고 선택한 안을 `direction.composition`에 보존한다. parts에는 원음 기준 `start/end`, 역할, 실제 `style` 또는 출발 `profile`, 사용할 기법, 전환 근거를 둔다. 현재 HTML의 profile 카드는 단일 프로젝트용이므로 이 배열을 자동 재생·합성하는 기능으로 소개하지 않는다. 채팅 비교표와 실제 짧은 영상, 구간별 편집 프로젝트를 함께 보여 주고 고른 안으로 제작한다.

예를 들어 같은 곡에 다음 세 안을 비교할 수 있다. 다른 곡에도 이 이름·개수·조합을 기계적으로 복사하지 않는다.

- **한 색의 임팩트 / single·bold**: crimson을 유지하며 큰 타이포, 단어 펄스, 비트 줌과 확실한 정지 구간.
- **경계선 확장 / adaptive·bold**: 같은 crimson 안에서 벌스의 정렬·여백 → 프리코러스의 간격/기울기 → 후렴의 큰 글자·패널·저역 확대 → 브리지 감산.
- **스테이지 전환 / multi-style·bold**: crimson의 벌스 → mint의 전자적 프리코러스 → acid의 후렴. 공통 한글 서체와 훅 모티프를 유지하고 마지막 후렴에서 변주.

## 장르·가사를 화면 문법에 연결

| 음악·내용 근거 | 조합의 출발점 | 강약·읽힘 설계 |
| --- | --- | --- |
| 베이스 힙합/강한 K-pop, 도전·전진 | crimson + mint/acid, 키네틱 단어·대각면·속도선 | 저역 어택은 확대, 중고역 어택은 짧은 위치/기울기 변화. 랩 본문은 읽히는 덩어리로 유지 |
| EDM/하이퍼팝, 드롭과 브레이크 | acid + synth80, 터널·색면·강한 카메라·글리치 | 드롭 전 감산→한 번 강한 진입→홀드. 가사와 무가사 구간의 효과량을 구분 |
| 시티팝/디스코, 야간 이동·밝은 회상 | synth80 + vapor/rouge, 네온·그라디언트·궤도 | 그루브의 반복과 유연한 움직임. 후렴에는 색·공간을 열되 매 박마다 스타일을 교환하지 않음 |
| 발라드/어쿠스틱, 친밀한 서사 | paper/kraft/gold 중 문맥에 맞는 방향 | 적은 스타일도 가능. 감정 반전·마지막 후렴에만 대비를 주고 긴 음절·여백을 보존 |

이는 편집 제안이며 장르 제한이나 공식 프리셋 규칙이 아니다. 실제 27개 스타일과 registry에서 확장한다. 두세 스타일을 출발점으로 삼을 수 있지만 상한은 아니다. 더 많은 스타일을 쓰는 안은 각 스타일의 역할과 전환 이유를 설명한다.

화려함을 모든 슬라이더의 최댓값으로 정의하지 않는다. 구간별 글자 크기·컷 호흡·기법 풀·카메라·배경·장식·색·효과 이벤트를 조합한다. `knWordPulse`, `knBeatLean`, `knTickShift`, `knShearKick` 같은 실제 부품과 등록된 전환/FX를 곡에 맞게 고른다. 글리치·큰 카메라를 일괄 금지하지 말고 필요한 구간에서 비교한다. 플래시 사용 여부는 별도 선택으로 두고 화려함 요청을 플래시 최대로 확대하지 않는다.

가사 등장 시각은 비트와 별개로 보존한다. 단어별 시각이 없으면 문장 전체를 먼저 읽히게 하고 비트가 크기·기울기·장식에 반응하도록 만든다. `cuts:1`이어도 움직임을 단조롭게 제한할 이유는 없다. 긴 가사의 native `visEnd` 조기 소멸, 확대 중 잘림, 대비 감소는 실제 완성 프레임에서 고친다. 효과를 모두 제거하는 것을 첫 해결책으로 삼지 않는다.

## 공식 엔진의 경계

고정 JIZURA 0.10.1은 전역 `project.style` 1개를 사용한다. `scheme`은 그 스타일 내부의 배색 번호다. `themeId`나 `chaos`는 시간순 스타일 전환 기능이 아니다. 다른 스타일의 lockedCuts를 복사해도 전체 배색·질감·서체 체계가 함께 보존되지는 않는다. [공식 스타일 해석](https://github.com/852wa/JIZURA/blob/fc16bfe43ea4a6c25a21f1caf04d17326de14f00/src/04_styles.js#L155), [planner](https://github.com/852wa/JIZURA/blob/fc16bfe43ea4a6c25a21f1caf04d17326de14f00/src/08_planner.js#L268)

단일/adaptive는 기존 native 한 프로젝트로 납품한다. multi-style은 아래 제작 계층을 사용하며, 이를 하나의 vanilla `.jizura.json`으로 포장하지 않는다. 기존 Studio는 각 구간 프로젝트 편집용이다. 최종 혼합 영상은 합성 결과 미리보기에서 확인한다.

## 여러 전역 스타일의 실제 제작

1. 같은 원음·원가사·타이밍으로 구간별 스타일 프로젝트를 만든다. 먼저 새 복사본을 만들고 기존 프로젝트를 덮어쓰지 않는다. 사용자 잠금은 보존하고, 자동 제작 스냅샷을 다른 연출로 바꿀 때는 그 복사본에서 명시적으로 다시 설계한다.
2. 기본 색상/악센트 override가 켜져 있으면 다른 스타일을 선택해도 예전 배색이 남을 수 있다. 의도한 공통색인지 확인한다. lockedCuts 안의 이전 배치·폰트·이벤트도 새 style을 자동으로 따라가지 않으므로 실제 plan을 검사한다.
3. 각 native 프로젝트를 원음 전체 시계로 유지하고, 기존 `exportRange:{from,to}`와 `render-jizura.mjs --render`로 필요한 부분을 렌더한다. 범위 버튼은 앞 여유 프레임을 포함할 수 있으므로 **result.json의 actualExportSpan을 사용**한다. 같은 출력 경로·동시 renderer를 쓰지 않는다.
4. 전환은 곡의 구조·구절·어택을 기준으로 정한다. 문장 중간의 스타일 전환도 의도할 수 있지만 원문·가창 시각을 밀어 전환점에 맞추지 않는다. 이 합성기는 hard cut이다. 전환 효과가 필요하면 native 구간 안에 설계하고 결과가 경계에서 잘리지 않는지 검사한다.
5. `compose`는 각 영상에서 원음 시각에 해당하는 프레임만 취하고, 원음을 한 번 잘라 넣는다. 구간 MP4의 오디오들을 이어 붙이지 않아 경계 AAC 패딩/무음이 누적되지 않는다. 여러 곡의 연결은 기존 `assemble`을 쓴다.

```json
{
  "audio": "/절대/원곡.mp3",
  "sourceSha256": "실제 64자리 원음 해시",
  "start": 0,
  "end": 166.038662,
  "segments": [
    {"start": 0, "end": 48.04, "project": "/절대/벌스.jizura.json", "render": "/절대/벌스-render/result.json"},
    {"start": 48.04, "end": 70.6, "project": "/절대/후렴.jizura.json", "render": "/절대/후렴-render/result.json"},
    {"start": 70.6, "end": 166.038662, "project": "/절대/복귀.jizura.json", "render": "/절대/복귀-render/result.json"}
  ]
}
```

```bash
python3 "$JIZURA_SKILL/scripts/project.py" compose \
  --manifest "/절대/스타일-조합.json" --out "/절대/새-조합영상.mp4"
```

start/end와 segments는 원음 초 단위다. start/end 생략 시 전곡이며, 부분 비교 영상이면 그 원음 범위를 명시한다. 각 segment의 실제 렌더 범위가 요청 구간을 덮어야 한다. 프로젝트의 원문·시계, 원음 해시, 규격·FPS, 간격/겹침을 검사하며 자동 속도 변경·빈 구간 메우기·원음 교체는 하지 않는다. 프레임 경계는 원음 누적 시계로 양자화하므로 비프레임 경계의 오차와 AAC 끝 패딩을 검수 JSON에서 확인한다.

인접 경계는 앞 구간의 end 값을 다음 start에 그대로 재사용한다. 각 구간에서 따로 계산·반올림해 작은 틈이나 겹침을 만들지 않는다.

## 검수와 납품

- 단일 비교안과 조합 비교안이 색만 다른 같은 반복인지, 타이포·카메라·효과의 구간 역할도 실제 달라졌는지 확인한다.
- 원가사·가창 시각·승인 추정 구간·원음 SHA가 스타일 변주 후에도 유지되는지 확인한다. 전환 직전/직후, 첫 발성, 빠른 랩, 반복 훅, 마지막 음을 검수한다.
- 예전 정렬이나 기능 검증 샘플의 미검수 상태를 스타일 합성 성공만으로 검수 완료로 바꾸지 않는다.
- 구간의 실제 style과 부품, exportSpan, 최종 경계 프레임·오디오 연속성, MP4 규격/길이를 확인한다. 기술 수치를 청취·가창 정답으로 확대하지 않는다.
- 최종 MP4 + 조합 manifest + 구간별 native 프로젝트/result/plan + 원문 cue/SRT와 정렬 상태 + 검증 JSON을 함께 남긴다. 기존 전곡을 원하지 않은 채 덮어쓰거나 전곡 재렌더하지 않는다.
