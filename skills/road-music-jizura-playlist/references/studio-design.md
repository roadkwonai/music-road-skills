# 추천과 커스텀 제작 화면 설계

대상은 음악을 가진 제작자다. 첫 화면의 일은 곡에 맞는 추천 방향을 확인하고 실제 JIZURA 프레임을 보며 설정을 고쳐 제작하는 것이다. 기존 CLI 제작·리듬 스코어·원음 해시·가사 시계는 유지한다. Road Music 앱과 공식 JIZURA 소스는 수정하지 않는다.

추천의 범위는 단일 스타일·동일 스타일 내 리듬 변주·여러 전역 스타일의 조합까지다. 현재 Studio는 native 프로젝트 하나의 편집기이므로 혼합안의 시간순 미리보기로 소개하지 않는다. 혼합안은 [스타일 조합](style-composition.md)의 실제 비교 영상·구간별 native 프로젝트·합성 manifest로 선택하고 제작한다.

## 공식 기능을 재사용하는 구조

`음악/기존 프로젝트/곡 해석 → 로컬 Studio → 같은 출처의 공식 한국어 편집기 → native 프로젝트 저장/MP4·PNG·AE 출력`

- Python 표준 라이브러리로 127.0.0.1 전용 서버를 연다. 세션 토큰, Host/Origin 검사, 지정된 자산과 음원만 제공하며 새 출력 폴더에만 저장한다. 임의 명령 실행이나 외부 게시 API를 두지 않는다.
- 공식 `ko/index.html`을 같은 origin iframe에 넣는다. 프로젝트와 음원은 native 파일 입력을 통해 불러오고 import 검증·폰트 복원·기록 초기화를 유지한다. 공식 엔진 27스타일/860부품을 HTML에서 다시 구현하지 않는다.
- 추천 화면은 실제 `J.ui.plan`을 `J.Renderer.frame`으로 그린다. 전체 편집 모드는 원래 JIZURA UI를 보여 주어 컷별 연출·기법 잠금·팔레트·폰트·탭 동기화·출력 기능을 그대로 사용한다.
- 곡 해석은 Codex가 작성한 direction/analysis를 우선한다. 브라우저 단독 장르/키워드 매칭은 보조 추천임을 표시한다. BPM만으로 장르·감정을 확정하지 않는다.
- 기본 추천은 현재 곡의 지정 profile과 이유를 보여 주고 공식 `J.omakase`로 세부 변주를 만든다. 원음·가사 시각·사용자 잠금을 유지한다. 고른 스타일을 재추첨으로 몰래 바꾸지 않는다.

## 화면

시원한 회백색 바탕 `#edf3f5`, 잉크 `#17222d`, 보조 글자 `#60717d`, 청록 `#147f7c`, 미세한 강조 `#e7bd5d`를 쓴다. 본문은 시스템 한글 고딕, 표시는 굵은 간결한 고딕, 시각은 monospace다. 장식보다 실제 미리보기와 곡 정보를 중심으로 배치한다.

```
JIZURA 음악 스튜디오              프로젝트 열기 / 설정 저장 / MP4 만들기
음악·장르·분위기·가사 해석        실제 엔진 미리보기 + 재생/탐색
추천 방향 / 적용 이유            스타일·강도·팔레트·출력 빠른 설정
                             [추천·빠른 설정] [JIZURA 전체 편집기] [기능 안내]
```

추천 화면에서 음원/가사를 연결하고 후보를 비교한다. 실제 엔진의 전체 스타일을 선택할 수 있다. 고급 편집에서만 의미 있는 설정은 공식 UI로 넘긴다. 화면비·해상도·fps·음원 포함·합성 배경·가운데 비우기는 실제 출력과 연결한다. 버튼은 한국어로 동작을 이름 짓고 입력/오류/저장 상태, 키보드 포커스와 작은 화면을 확인한다.

빠른 설정에는 `?` 도움말을 붙여 마우스 오버·클릭·키보드 포커스로 설명을 확인하고 Esc로 닫는다. 드롭다운의 선택지는 `한국어 이름 — 간략한 설명`으로 표시하며 원래 value는 보존한다. 스타일 설명은 공식 엔진의 한국어 설명을 재사용한다.

## 저장과 범위

설정 저장은 새 revision 디렉터리에 native `.jizura.json`, direction과 현재 plan을 남긴다. 원음의 실제 SHA-256과 로컬 경로를 연결한다. 브라우저에서 새로 고른 음원은 로컬 세션 폴더에 복사해 이후 CLI 제작에도 사용할 수 있다. 원본을 변경하지 않는다. 음원과 업로드 폰트 바이너리는 native JSON에 포함되지 않는다는 점을 화면에서 알린다.

이미 baked된 컷은 native lockedCuts를 유지한다. 아직 bake되지 않은 directing 스코어는 음원을 확인한 뒤 기존 helper로 고정한다. 사용자 수정 이후 저장은 현재 native 상태가 우선하며, 예전 스코어를 다시 적용해 수정을 되돌리지 않는다. 초기 해석/스코어는 provenance로 별도 보존한다.

MP4 버튼은 공식 native 출력이며 PNG/투명 전후경/LRC/AE는 전체 편집기에 연결한다. 전체 길이와 원음 연결이 필요한 최종 납품은 기존 assemble로 마무리한다. 부분 범위·무음·투명 레이어 출력은 의도한 모드로 표시한다.

## 검수

1. 공식 웹의 간단/고급, 스타일·연출·기법·내보내기 탭과 실제 설정값을 수집해 pinned 소스와 대조한다.
2. 저장 프로젝트의 스타일·효과·색·폰트·타이밍·종횡비·잠금이 재열기 후 유지되는지 확인한다.
3. 추천 적용 전후에도 원문 가사/고정 시각/음원 해시가 유지되는지 확인한다.
4. 로컬 서버는 외부 Origin·잘못된 토큰·경로 탈출·덮어쓰기를 거부하는지 검사한다.
5. 브라우저에서 음원 가져오기→추천/커스텀→설정 저장→재열기→짧은 실제 MP4까지 실행한다. 자동 수치 검사를 청취/가창 정답 검수로 확대하지 않는다.
