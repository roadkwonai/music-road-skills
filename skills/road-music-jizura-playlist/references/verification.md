# 보완 검수 기록

확인일: **2026-10-17**, macOS / 로컬 JIZURA **0.10.1** (`fc16bfe43ea4a6c25a21f1caf04d17326de14f00`). 공식 소스는 수정하지 않았다. 웹 분석·상호작용은 사용자 지정 Ego Browser로 진행했다.

## 출처와 설계

- `jizura.net/ko/`는 당시 v0.10.0을 표시했다. 실제 UI에서 간단/고급, 스타일·연출·기법·출력, 가사/음원 입력과 MP4를 확인했다.
- GitHub HEAD와 로컬 소스는 모두 위 SHA / VERSION 0.10.1이었다. README 첫머리의 v0.9.0 표기와 구분했다.
- 공식 Git 트리에서 별도 Codex/Claude `SKILL.md` 배포를 찾지 못했다. 이 스킬은 공식 엔진을 활용하는 개인 스킬이다.
- 브라우저와 실행 소스에서 27스타일 / 860부품을 확인했다. [28개 기능 분석](official-features.md), [기획·설계](studio-design.md)에 필드와 출처를 정리했다.

## 실제 브라우저 사용

1. 합성 비트 음원과 한국어 **검수용 문구**로 시험했다. 실제 노래 가사나 청취 평가 자료로 사용하지 않았다.
2. 서로 다른 추천 3개, 전체 스타일 27개가 표시되고, 수동으로 고른 스타일이 재구성 때 다른 profile로 되돌아가지 않는 것을 확인했다.
3. 추천·재구성 뒤 원문, 고정 시각과 lockedCuts가 유지되었다. 실제 원음 시계로 빠른 미리보기가 진행되었다.
4. 공식 편집기의 fps 변경이 빠른 설정과 저장본에 반영되었다.
5. 새 음악을 부모/공식 편집기 양쪽에서 가져왔다. 원문과 snap 선택을 보존하고, 음원이 달라진 검수 필요 상태가 저장·새로고침 후에도 유지되었다.
6. 업로드 Noto Serif KR 폰트(14,062,572바이트)를 저장하고 **다른 포트**에서 복원했다. 누락 폰트 0개였고, 깨끗한 CLI 렌더 프로필에서도 실제 자산을 복원했다.
7. 웹에서 만든 커스텀 프로젝트가 브라우저와 CLI에서 모두 H.264 **1280×720 / 30fps / 180프레임**, AAC로 출력되었다. 비디오는 6.000초, AAC 패딩을 포함한 컨테이너는 6.080초였다. 프레임 길이와 컨테이너 패딩을 구분했다.
8. 공식 `J.exportPNGZip`으로 투명 전후경 샘플을 출력했다. back/front PNG 6개, RGBA 및 실제 투명 픽셀을 확인했다. `J.planForAE`로 실제 AE JSON(컷 2개)을 생성했다. UI의 ZIP 다운로드 이벤트 수집은 확인되지 않아 이 항목은 공식 API 산출물을 검증했다.
9. 새 음악을 넣을 빈 화면에서 가짜 가사가 없고 추천이 3개임을 확인했다. 420px 화면에서 가로 넘침이 없었다. 실제 Canvas 프레임은 열어 확인했다.

## 독립 검수와 한계

독립 검수에서 발견한 미적용 스코어 삭제, 다른 원음에 스코어 적용, 검수 상태 유실, 추천 설명의 HTML 삽입, 초기화 실패 잔류, 설정 표시 불일치를 수정했다. 원음만 바꿔도 사용자 가사를 지우지 않도록 보완했다.

공식 편집기 안에서 세션 도중 다른 프로젝트를 여는 경우 현재 서버가 모르는 폰트 자산은 재업로드 또는 `--project` 새 세션 복원이 필요하다. 전체 페이지 스크린샷은 Ego CDP 타임아웃으로 확인하지 못했으며, DOM·반응형 경계와 실제 Canvas 프레임을 검사했다. Ego Lite 업데이트 알림은 확인했고 업데이트는 실행하지 않았다.

장시간 4K·60fps 전체 곡, 실제 After Effects 앱의 실행/재생, 모든 860부품 조합과 실제 보컬의 정밀 가창 싱크는 이번 검수 대상이 아니다. 브라우저 단독 업로드는 리듬/키워드 보조 추천이며 Codex의 가사 의미·장르 해석과 구분한다.

## 한국어 테마와 설정 도움말 보완

같은 날 빠른 설정의 도움말 18개, 드롭다운 7종의 선택지 60개를 보완했다. 선택지는 `옵션명 — 설명`으로 표시하며, 테마 6종은 한국어로 통일했다. 공식 편집기 안의 두 테마 선택기도 같은 이름과 설명을 표시한다. 스타일 설명은 엔진의 한국어 `desc`를 재사용한다.

Node 구문·기존 회귀검사와 테마 한국어/엔진 설명 재사용 검사를 통과했다. 실제 브라우저에서 선택지 전체에 설명이 있는지, 화면비의 암시적 value를 포함한 원래 키가 보존되는지 검사했다. `kinetic / 9:16 / 1080 / 30 / black`을 선택했을 때 native 프로젝트의 값과 자료형이 일치했다. 도움말의 hover·키보드 포커스·Esc 닫기, 420px 화면에서 툴팁과 본문의 가로 넘침 없음도 통과했다. Codex 브라우저의 실제 도움말 표시 화면을 캡처했다. 이번 표시 보완에서는 MP4를 다시 렌더하지 않았다.

## 2026-10-18 단일·리듬 변주·멀티스타일 보완

추천 규칙을 단일 전역 스타일, 같은 스타일 안의 구간별 변주, 여러 전역 스타일의 조합까지 확장했다. 구성 방식과 화려함을 별도 축으로 두며, 단일 스타일 선호와 기존 가사·시각·잠금을 보존한다. 공식 웹을 Ego Browser로 재확인한 결과 화면 v0.10.0, 로컬/GitHub VERSION 0.10.1과 같은 SHA였다. 공유 runtime은 수정하지 않았다.

`project.py compose`를 추가했다. 같은 원음 SHA와 lyrics/timing/cutTime 시계를 가진 native 구간 영상들을 actualExportSpan 기준으로 자르고 원음을 한 번만 넣는다. 누적 경계는 선택한 원음 범위 시작에 고정된 프레임 시계로 계산하며, 실제 선택 프레임과 출력 원음 시계의 차이를 sidecar에 기록한다. 기존 여러 곡용 assemble 경로도 유지했다.

- `python3 -B scripts/test_project.py`: **12개 통과**. 기존 build/assemble 회귀검사와 실제 색 영상의 부분범위·비정수 경계·preroll·스타일 경계색·프레임 수·오디오 연속성을 포함한다. 다른 SHA/시계/규격/렌더 메타데이터, 빈틈·겹침·NaN·원음 범위 초과·부족한 exportSpan·기존 출력은 거부했다.
- 변경 Python AST와 skill-creator quick_validate 통과.
- 같은 원곡 47.79–62.86초로 **crimson → mint → acid** native 프로젝트를 각각 렌더한 뒤 실제 합성했다. H.264 1280×720 / 24fps / 362프레임, 오디오 15.070초 / AAC 48k stereo. 스타일 경계는 출력 141·227프레임이며 각 선택 프레임의 원음 시계 오프셋은 0초였다.
- 실제 plan에서 hold/cam/treat/bg가 각각 `knWordPulse/beatPunch/knWordScale/none`, `knTickShift/knShearKick/knWordPlate/hexGrid`, `knBeatLean/beatPunch/knWordPlate/squareTunnel`로 달랐다. 전체 원문·가사 시각 signature는 같았다. 실제 합성 프레임을 열어 세 스타일과 원문을 확인했다.
- 같은 원음 구간 대비 합성 오디오 파형 상관은 **0.999770**, 스타일 경계에 추가 무음은 관측되지 않았다. 청취 품질·정밀 가창 싱크 검수와 구분한다.
- 독립 전방 테스트에서 기존 HTML이 조합 카드를 표시하지 않는 경계를 지적받아, 본문과 조합 문서에 채팅 비교·실제 미리보기·구간 프로젝트 편집 경로를 명시했다. 해당 약속의 모순이 남지 않았다는 후속 읽기 전용 검수는 통과했다.

실제 기능 검증 자료는 `<local-home>/Music/JIZURA/20261018-style-composition-jup7wzz4/verification.json`, 합성 manifest는 같은 폴더의 `composition.json`이다. 이번에는 기능 검증용 부분 영상만 만들었고 전곡을 다시 제작하지 않았다. 현재 Studio는 단일 프로젝트 편집 화면이며 멀티스타일 통합 타임라인 UI를 새로 구현한 것은 아니다. 기존 가사 정렬의 미검수 상태도 그대로 유지했다.
