# 완성본 전용 Output 구조 전환

## 목적과 경로

`Output/<음악명--sourceSHA12>/<프로젝트명--projectID12>/<YYYYMMDD-HHMMSS[-충돌번호]>/`에는 검증된 최종 음원·영상·가사·자막·최종 스토리보드만 둔다. 제작 중 입력·설정·재개 자료·캐시는 `.roadmusic/work/<musicId>/<projectId>/`에 둔다. `.roadmusic/history.sqlite3`에는 프로젝트·버전·파일 해시/크기·요청 스냅샷·변경 사유만 저장하며 미디어 BLOB은 저장하지 않는다.

새 제작이 기존 `Output/` 아래 경로를 요청하면 실제 작업 루트를 `.roadmusic/work/`로 돌려 주고, 게시 검증이 끝날 때에만 시간 버전을 만든다. 같은 내용은 중복 게시하지 않는다. 이미 완료 표시가 난 프로젝트도 이 경로로 다시 들어오면 기존 Output을 작업 루트로 쓰지 않고 현재 work 루트로 연결한다.

## 공개 명령과 중단 조건

먼저 `storage:restructure-status`로 준비 상태·차단 사유를 읽고, `storage:restructure-preview`로 일회용 계획을 만든다. 실제 실행은 반환한 48자 `planId`를 넣은 `storage:restructure-cleanup --confirm`만 사용한다. 임의 경로나 셸 삭제로 대체하지 않는다.

`preparing` 또는 `prepared` 상태인 전환은 publish를 막는다. 원본·등록 최종본·활성 작업·필수 이력·모델이 검증되지 않거나 파일이 계획 뒤 바뀌면 중단하고 새 상태를 다시 조회한다. 이전 작업의 수정 사유가 없으면 추측하지 않고 `수정 사유 미기록`으로 남긴다.

## 검증과 정리 경계

전환은 원음 SHA, 등록된 최종 파일 해시와 보존 대상의 실제 존재를 확인한 뒤에만 이전 자료를 정리한다. 알려진 YuE canonical 복구는 파일 전체를 메모리에 적재하지 않는 스트리밍 검증으로 처리한다. 검증 또는 복사가 실패하면 원본을 유지한다.

과거 레거시 폴더를 자동으로 넓게 지우지 않는다. 후보는 공개 미리보기의 검증 결과로만 선택하고, 준비·활성·변경·누락 항목은 보호 사유와 함께 남긴다. 완료 보고에는 실제 디스크 여유 변화와 작업 폴더에서 줄어든 할당량을 구분한다. 모델을 별도 위치로 옮겨 확보한 공간은 구조 전환의 확보량에 합산하지 않는다.

## 기존 모델을 쓰는 격리 검증

실제 생성 검증이 필요할 때만 `setup:test-profile`로 존재하지 않는 새 절대 경로를 준비한다. 반환된 `env.ROADMUSIC_DATA_DIR`를 그 검증의 후속 공개 CLI 명령에만 적용한다. 이 명령은 기존 runtime·모델을 복사하거나 심볼릭 링크하지 않고, 원본 라이브러리·로그인 정보·deliveryRoot를 새 프로필에 옮기지 않는다. 서비스 시작·중지와 엔진·모델 설치도 하지 않는다.

기존 ACE 설치 표지는 공유 runtime의 venv Python과 Turbo 모델 파일이 모두 확인될 때만 새 프로필에 기록된다. 확인할 수 없으면 엔진 설치를 대신 실행하지 말고 미설치 상태를 보고한다.
