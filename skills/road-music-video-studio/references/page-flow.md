# 제작 단계별 페이지 열기와 확인

음악·영상 작업의 현재 단계에 필요한 화면을 실제로 연다. HTML 파일이나 준비 URL을 만들었다는 사실만으로 사용자에게 화면이 열렸다고 보고하지 않는다. 기존 프로젝트·원음·선택을 보존하고, 이미 열린 같은 페이지를 불필요하게 다시 로드하지 않는다.

## Ego 브라우저

기본 자동 열기는 `ego-browser`의 기존 Road Music 페이지 한 개를 재사용한다. 같은 주소는 다시 로드하지 않고, 제작실·카탈로그·JIZURA·선택기·검수 화면이 필요하면 같은 탭의 주소만 바꾼다. 서버가 준비됐다는 이유로 별도 `open` 명령을 덧붙이지 않는다.

현재 작업의 Ego TaskSpace가 이미 있으면 `ROADMUSIC_EGO_TASK_SPACE=<정수 ID>`를 CLI와 각 Python `--open`에 동일하게 전달한다. 없으면 전용 `Road Music 제작실`을 재사용하고, 이전 버전의 에이전트 생성 Road Music 공간이 하나만 있으면 알려진 페이지와 로컬 주소를 확인해 재사용한다. 사용자가 요청한 한 페이지 재사용에 따라 완료 후 남긴 전용 페이지도 다시 연결하며, 임의 사용자 생성 공간은 가져오지 않는다. 후보가 여러 개이거나 제어 오류가 나면 새 탭·다른 브라우저로 우회하지 않고 실패를 알린다.

이 동작은 OS 기본 브라우저 설정을 바꾸지 않는다. 사용자가 OS 브라우저를 명시한 경우만 `ROADMUSIC_STUDIO_BROWSER=system`을 쓴다. 완료 페이지 재연결을 원하지 않으면 `ROADMUSIC_EGO_REUSE_ROAD_MUSIC_PAGE=0`을 쓴다. 자동화에서 창이 필요 없으면 `--open`을 생략하거나 `ROADMUSIC_STUDIO_AUTO_OPEN=0`을 쓴다. 사용자가 제어를 중단시키면 자동으로 다시 가져오지 않는다.

## 단계별 화면

| 단계 | 열 화면과 동작 | 다음 단계 전 확인 |
| --- | --- | --- |
| 명시적 CLI 시작 | `service:start`의 제작실 자동 열기. 기존 유효 서버 재사용 | Ego의 실제 URL·제작실 제목·공통 메뉴 |
| 곡·제작 방식 선택 | 공통 `studio.py serve --project ABS --review --open` | 음원 재생, 실제 샘플, 기존 선택 유지 |
| 별도 Showreel 선택이 필요한 경우 | `cd_presets.py choose --out NEW_ABS --music ABS --open` | 실제 프리셋과 네 표시 항목. 공통 제작실에서 이미 고른 선택을 중복 요구하지 않음 |
| JIZURA 직접 편집 | `studio.py --out NEW_ABS --audio ABS [--project ABS] --open` | 추천·설정/전체 편집기와 별도 가이드 링크, 현재 원음과 프로젝트 일치. 조합 전곡을 한 native 프로젝트로 오인하지 않음 |
| 스토리보드·가독성 검수 | 실제 생성된 검수 HTML을 같은 Ego 공간에서 열거나 공통 제작실에 등록 | 실제 프레임·원문·추정/확정 표시·이전 페이지로 복귀 |
| 완성 파일 납품 | `publish` 후 같은 탭의 `/works/`에서 해당 음악 그룹 상세로 이동 | 영상·음원·원가사·SRT/LRC 개별/ZIP 다운로드, 목록/크게 보기와 원본 일치 |
| 결과 검수 | 음악 상세의 `#work-records` 내부 메뉴 | 원가사/자막 미리보기, 스토리보드·영상 대조, 의견과 승인 상태, 미저장 의견 왕복 유지 |
| 기능 설명 | `/guide/` 또는 `/guide/<slug>/` | Markdown 원문과 HTML 일치, 복사·수동 복사·주제별 링크 |

원음·프로젝트가 없거나 엔진이 미설치이면 해당 화면에서 사실대로 안내한다. 렌더를 시작하지 않은 선택·요청 저장 버튼을 자동 영상 제작 완료로 설명하지 않는다.

## 정상·실패 검수

- 준비 이벤트 뒤 실제 페이지 제목과 화면을 확인한다. 열기 실패는 URL 준비 성공과 구분하고 같은 세션에서 원인을 해결한다.
- 페이지 왕복·탭 변경 뒤 임시 선택/피드백을 확인한다. 원음이 바뀌면 과거 가사 시각을 복원하지 않는다.
- 빈 입력·저장 중·성공·네트워크 실패를 확인하며, 오류가 접힌 영역에 숨지 않게 한다.
- 독립 HTML은 상대 글꼴·미디어 경로를 확인한다. 실행 중 토큰을 배포용 원본 템플릿에 넣지 않는다.

### 소리가 들리지 않을 때

- 실제 사용자가 보고 있는 공간·탭·서버 주소부터 맞춘다. 비활성 공간이나 이전 서버의 재생을 현재 화면의 검증으로 대신하지 않는다. 재생 시간 진행·디코딩·RMS는 파일/신호 근거이며 헤드폰으로 들렸다는 근거가 아니다.
- 같은 원음의 시스템 재생과 현재 브라우저 재생을 하나씩 구분해 확인한다. 사용자가 같은 브라우저의 다른 사이트에서는 들린다고 하면 OS 전체 출력 문제로 단정하지 말고 해당 사이트·탭·미디어 경로를 조사한다. 물리 출력 장치나 음량을 임의로 바꾸지 않는다.
- 기존 선택을 보존한 뒤 필요한 경우에만 새로 고침 또는 새 브라우저에서 같은 원음을 확인한다. 새 브라우저에서 정상이라는 사용자 확인이 있으면 그 결과와 기존 탭에서의 현상을 구분해 기록하고, 확인되지 않은 원인을 핑계로 재생 코드를 계속 바꾸지 않는다.

한 페이지의 역할은 하나만 둔다. 제작실에 결과 목록이나 검수 폼을 다시 넣지 않고 전용 페이지로 연결한다. 문서는 `assets/guides`의 Markdown을 먼저 편집하고 Python/Node 생성기의 공통 가이드 렌더러를 사용한다.
