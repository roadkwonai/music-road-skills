# ACE·YuE CCM 전문 제작 가이드

**CCM 제작 기본 안내**에서는 기존 CCM 지식의 스타일 분류와 엔진별 상세 조합 프롬프트를 함께 찾습니다. [CCM 전문 페이지 열기](/ccm/) · [일반 공개 명령 조합](/recipes/) · [공개 명령 레퍼런스](/reference/)

## 읽고 활용하는 순서

1. 회중 예배·특송·개인 기도·묵상 연주·절기 가운데 목적을 정합니다. 신앙의 대상과 주제를 명확하게 쓰고, 제공한 원문은 그대로 보존합니다.
2. 전문 페이지에서 ACE·YuE 전용 버튼으로 엔진 하나를 고릅니다. 기본값은 YuE이며 전체 보기로 초기화해도 YuE로 돌아갑니다. 용도·장르/스타일·태그로 더 좁힙니다. 여러 필터가 함께 적용되므로 결과가 없으면 **전체 보기·필터 초기화**를 누릅니다.
3. 카드의 **프롬프트와 사용 방법 자세히 보기**를 펼칩니다. 편성·보컬·가사·구조를 왜 조합했는지 읽고 필요한 요소만 바꿉니다.
4. 기본 프롬프트를 복사하거나 **기본 요청과 변경 내용 복사**로 기본 요청과 바꿀 범위를 함께 복사해 새 제작 요청에 붙입니다. 명령 순서는 각 공개 기능의 역할을 설명하며, 복사 버튼은 제작을 실행하지 않습니다.
5. 실제 입력과 가사를 검토한 뒤 승인한 범위에서 생성하고 전체 가창·길이·잘림과 결과물을 확인합니다.

## ACE의 CCM 제작

**간결한 편곡 의도**를 먼저 정합니다. 장르, 주악기, 보컬, 감정, 구간별 에너지 순서로 적습니다. 회중 찬양은 과밀한 반주·매 줄 달라지는 고음·장식보다 따라 부르기 쉬운 일관된 후렴을 요청하는 편이 좋습니다. 이는 편곡 의도이며 특정 음역·가창을 확정하는 제어가 아닙니다.

`prompt:compose`·`lyrics:check`·`song:prepare`로 실제 전달본을 확인합니다. 악기·BPM 등 모든 문구가 합쳐진 caption은 512자, 정리된 가사는 4,096자 이내인지 확인합니다. YuE의 ABC·계획·advanced 옵션을 ACE에 넣지 않습니다.

## YuE의 CCM 제작

`yue`와 `yue-mlx`는 설치된 플랫폼과 사용자 선택을 유지합니다. `yue:capabilities`와 현재 schema로 실제 지원 기능을 확인합니다. ACE의 문자 한계나 초기 YuE-v1의 규칙을 현재 YuE2에 적용하지 않습니다.

- **새 선율·새 화성**: 현재 계획 모드와 입력을 확인해 준비합니다.
- **가사 수정 우선**: 이전 ABC를 무조건 재사용하지 않습니다. 새 가사 전달과 이전 선율 보존 중 우선순위를 정합니다.
- **선율 보존 우선**: 원본을 덮어쓰지 않은 후보 ABC를 비교합니다. 가사/style을 바꾼 경우 전체 수정 입력과 검증한 abc를 새 song:generate에 전달합니다. 기존 가사/style을 그대로 둘 때만 song:render로 악보를 수정합니다. 실제 가창·파형 동일성은 보장하지 않습니다.
- **계획과 음원**: song:prepare는 무추론 입력 확인, mode:plan은 악보 모델 추론, mode:song은 음원 생성입니다. 저장 plan을 재사용하는 replay는 새 ABC 작곡이 아닙니다.
- **고급 샘플링 비교**: 같은 가사·악보·seed에서 적용되는 공개 옵션 한 항목만 바꿉니다. 제공 ABC는 계획 샘플러를 우회하며 CFG는 semantic·ODE는 acoustic 단계입니다. 높은 값이나 더 긴 계산이 음질 향상을 보장하지 않습니다.
- **실제 길이**: 목표 초는 기록값이며 정확한 생성 길이 제어가 아닙니다. 자연 종료(EOS), 토큰 상한의 잘림, 목표 대비 실제 길이를 구분합니다.

## 공통 CCM 고급 응용을 고르는 기준

회중 워십, 작은 교회 밴드, 피아노 특송, 가스펠 응답, 청년 팝록, 일상 CCM R&B, 로파이 묵상, 기도 앰비언트, 절기·공동체 축복처럼 사용 장면부터 좁힙니다. 가사의 신앙 대상과 메시지를 유지한 채 편성이나 전개 한 요소씩 조정하면 비교 이유가 명확해집니다.

기존 48개 스타일은 **CCM 스타일별 프롬프트**에서 펼쳐 봅니다. 각 항목에서 스타일의 용도와 편성 방향을 먼저 읽고, **영문 스타일 태그 복사**로 짧은 스타일 문구만 복사하거나 **YuE 또는 ACE 제작 요청 복사**로 엔진별 요청문을 복사할 수 있습니다. 스타일 분류는 실제 생성한 오디오 샘플이나 성능 순위가 아닙니다. 장르를 바꾼 서로 다른 곡은 별도 요청으로 만들며 `count`를 서로 다른 장르를 한꺼번에 생성하는 값으로 해석하지 않습니다.

## 생성 전에 확인할 것

- 한국어 제목·가사 전체와 반복 후렴을 읽어 어색한 표현·신앙 대상의 모호함을 확인합니다. 승인 원문을 조용히 개사하지 않습니다.
- 가사에는 부를 문장과 지원 구조만 넣고 지시문·미지원 태그를 가창 문장과 섞지 않습니다.
- 찬송 원전·한국어 번역·현대 편곡·기존 녹음은 권리를 따로 확인합니다. 원전의 만료가 특정 번역·음원 사용 허락은 아닙니다.
- 특정 편성·음역·박자 느낌은 요청 방향입니다. 원곡 선율이나 원하는 가창이 자동 보존된다고 약속하지 않습니다.

## 제작 후 확인할 것

실제 원문 가창, 누락·추가·반복·다른 언어 전환, 처음·중간·마지막 구간, 실제 길이·잘림을 확인합니다. 자동 전사 지표와 직접 청취 판정은 구분하고, 불명확한 전사만으로 반복 전곡 생성을 권하지 않습니다. 최종본과 요청·설정·변경 사유의 최소 이력을 남기고 재생성 가능한 중간 캐시는 공개 저장공간 미리보기로 정리합니다.

## CLI에서도 같은 자료 읽기

CLI 폴더에서 아래 지식을 읽습니다. 읽기만 하며 모델 설치나 생성을 하지 않습니다. 실제 지원 주제는 현재 설치본의 `prompt:knowledge` schema를 확인하세요.

### YuE 모델의 CLI 지식 조회

```bash
node cli/road-music.js prompt:knowledge --json '{"topic":"ccm"}'
node cli/road-music.js prompt:knowledge --json '{"topic":"ccm-advanced"}'
node cli/road-music.js prompt:knowledge --json '{"topic":"ccm-recipes"}'
node cli/road-music.js prompt:knowledge --json '{"topic":"yue-advanced"}'
```

### ACE 모델의 CLI 지식 조회

```bash
node cli/road-music.js prompt:knowledge --json '{"topic":"ace"}'
node cli/road-music.js prompt:knowledge --json '{"topic":"ccm"}'
node cli/road-music.js prompt:knowledge --json '{"topic":"ccm-recipes"}'
```

### 공통 자료의 원천

기존 CCM 문서에는 스타일 레시피, 창작 가사와 입력 JSON이 있습니다. 새 고급 문서는 ACE·YuE의 단계별 활용과 조합을 보강하며, 전문 페이지의 상세 카드는 공용 JSON 지식과 같은 자료를 읽습니다.
